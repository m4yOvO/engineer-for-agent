# 按条件选择的工程能力地图

这是需求与证据索引，不是固定架构。ID 便于计划、审查和改动互相引用；不对应固定模块、表或服务数。

先分开判断：数据敏感性、动作风险、持续时间、恢复承诺、并发规模和运维能力。小流量也可能有高风险动作；大流量只读服务未必需要人工审批。框架或托管平台的等价能力可以直接计入覆盖，但要核对配置、语义和证据。

## C01 产品承诺与边界

阶段协议：[工程阶段入口](engineering-workflow.md)。

**适用**：所有 Agent 工程。先区分“返回结果即可”“可丢弃进度”“必须恢复”“不得重复某业务动作”等不同承诺。

- 任务成功由业务结果定义；执行器返回成功不等于答案正确或业务合理。
- 确定使用者、任务时限、允许失败方式、人工接管、成本与数据边界。
- SLO/容量/保留时间由需求与测量决定，示例数字不是默认标准。

**证据**：代表性任务与失败故事、边界/假设表、可测的验收条件。无法量化时记录待测基线。

## C02 入口、身份与外部契约

阶段协议：[接口协议](stages/interfaces.md)。

**适用**：函数/CLI/RPC/HTTP/消息入口都存在合同；只有网络/多用户场景才需要对应网络认证机制。

- 输入、输出、错误、版本、重复请求、取消与结果获取语义明确。
- 异步受理与任务完成分开，任务身份、会话身份、业务意图身份不混用。
- 信任来自认证上下文或明确本地用户边界，不来自模型自报。

**证据**：协议定义、调用样例、拒绝/重复/断线场景。详见 [接口与数据](engineering-workflow.md)。

## C03 状态、事实与数据生命周期

阶段协议：[数据与存储协议](stages/data-and-storage.md)。

**适用**：需要跨调用状态、查询历史、恢复、审计、计费或长期记忆时；纯函数可仅有输入输出。

- 每类事实有拥有者、写入约束、查询权限与保留策略；区分当前状态、历史、恢复状态、动作尝试、业务结果。
- 同一原子业务变化的本地记录一起提交；跨存储需说明一致性/修复机制。
- 暂停、继续、取消和收尾有共同成立的事实、确认点与交接责任；参见 [操作一致性契约](stages/state-and-lifecycle.md#操作一致性契约)。
- 恢复快照、长期记忆、审计和缓存职责不同；不强制独立建表。

**证据**：逻辑数据图、实际持久适配器、约束/查询、重启与删除测试。不要把持久化直接等同灾备。

## C04 状态机、执行控制与可恢复性

阶段协议：[状态与生命周期协议](stages/state-and-lifecycle.md)。

**适用**：多步骤、长任务、人工等待、昂贵重算或跨进程恢复承诺。

- 循环、图节点、activity、actor 或插件回调的完成边界与重入语义明确。
- 能区分完成、失败、待人、取消、未决外部动作；状态集合按产品/引擎设计。
- 恢复点包含必要版本、进度和执行上下文；恢复不重置次数/预算限制。
- 等待不占用昂贵执行槽；取消有安全点和在途动作处置。

**证据**：各关键边界退出再恢复、重复继续、过期批准、旧快照读取。参考 [架构适配](architecture-adapters.md)。

## C05 队列、调度、并发与故障拥有者

阶段协议：[队列与执行权协议](stages/queue-and-execution.md)。

**适用**：异步受理、多执行者、分支并行或容量缓冲；同步单进程不必另建队列。

- 持久受理到执行之间有可靠交接；已有工作流调度可直接承担。
- 重复/迟到投递、失去执行权、租约接管、并行合并有明确定义。
- 重试由指定层管理，退避/抖动/截止/次数与死信或人工处理配套；避免层层重试叠乘。
- 并发与速率分开，保护下游与用户公平性；同进程控制不宣称集群保证。

**证据**：重复投递、并发竞争、执行者失联、积压恢复、重试耗尽场景。

## C06 工具、外部副作用与审批

阶段协议：[工具调用记录与恢复协议](stages/tool-execution.md)。

**适用**：所有工具需适当输入/输出约束；只有有相关风险的写入才需要对应幂等、核实、审批或补偿。

- 工具调用实际经过身份/资源/业务规则检查；MCP 与插件接入不自动得到豁免。
- 区分同一业务意图与合法的新动作，操作身份与尝试身份分离。
- 决策、调用、动作、尝试、持久结果和后续消费可关联；部分成功与回填中断不重做已完成工具。
- 外部成功但本地确认丢失有恢复方案；未知不能当失败盲重发。
- 对异步完成或可变化的业务结果，区分受理/终局，核对已成功记录与下游差异，处理迟到/乱序通知。
- 审批与具体动作内容/版本绑定，执行前复核变化条件；审批强度由风险决定。

**证据**：越权/参数冲突/重复动作、成功后崩溃、权威查询失败、审批后改参数。详见 [执行与恢复](engineering-workflow.md)。

## C07 模型适配与决策边界

阶段协议：[模型与上下文协议](stages/model-and-context.md)。

**适用**：调用模型、切换 provider 或依赖结构化决策。

- 统一内部语义但保留各模型支持差异；工具调用 ID、消息角色、流式结束与 usage 合同明确。
- 结构校验、受限修复、超时、拒绝/截断、fallback 有定义；不把非法输出当成功。
- 可追溯实际模型、提示词/工具/策略配置和版本；成本估算与实测分开。

**证据**：真实适配器合同测试、异常/部分响应/fallback 检查。模型升级与语义变化纳入评测。

## C08 上下文、记忆、检索与产物

阶段协议：[模型与上下文协议](stages/model-and-context.md)。

**适用**：长上下文、跨会话记忆、RAG、共享知识、文件/报告输出。

- 会话状态与长期知识分开；记忆写入有来源、权限、有效期、纠错/删除语义。
- 检索按权限过滤，来源文本不能提升权限；压缩后仍保留恢复/审批所需事实。
- 大对象与引用、完整性、访问授权和清理策略明确；分支/子 Agent 不误共享秘密。

**证据**：跨用户读取拒绝、删除传播、陈旧数据、恶意检索文本、压缩后继续工作、产物访问检查。

## C09 安全、隔离与扩展生命周期

阶段协议：[安全与资源协议](stages/security-and-resources.md)。

**适用**：按信任边界选择；代码/浏览器/插件与远程连接需要关注宿主权限、网络出口和清理。

- 权限由模型之外执行；最小可用能力、明确工作区/网络/凭据边界。
- 不可信代码隔离；容器、扩展 Hook、MCP 不是天然安全边界。
- 动态插件服务依赖、卸载清理、监听器/子进程取消可控；配置与实际执行一致。

**证据**：受限路径/出站请求、重定向、缺失权限、插件卸载、故障清理与脱敏检查。见 [安全与资源](stages/security-and-resources.md)。

## C10 配额、时间与成本

阶段协议：[安全与资源协议](stages/security-and-resources.md)。

**适用**：模型/工具消耗资源，尤其多调用、多分支或共享预算。

- 次数、并发、时长、输入/输出规模与费用限制在调用前生效。
- 硬预算有原子预留与结算或等价保证；未知费用待核实，软预算如实标注。
- 子任务、重试、修复、fallback 与恢复全部计入相关额度。
- 时间上限区分告警与截止、活跃时间与墙钟时间，规定跨层传递及恢复计时；见 [时间合同](stages/security-and-resources.md#超时截止与剩余时间)。

**证据**：并发耗尽、进程退出、重复结算、流中断、恢复后额度不刷新。无需强制使用计费数据库。

## C11 结果、进度与可观测

阶段协议：[事件与可观测协议](stages/events-and-observability.md)。

**适用**：所有执行需足够故障解释；流式补发仅在产品要求时提供。

- 当前状态、进度、日志、指标、Trace、审计分别服务相应读者。
- 有任务/调用/分支等关联信息，控制敏感数据和高基数指标。
- 声称可接续的事件有持久来源、游标与去重；实时临时 token 可明确为非持久。
- 慢客户端/观察器失败不应破坏执行；告警对应行动。
- 持续订阅按需限制连接、处理授权变化与历史过期，用明确水位重同步；见 [观察器生命周期](stages/events-and-observability.md#长连接授权与保留期)。

**证据**：一次任务定位、断线/慢消费者、事件权限、终态与最后事件、指标告警。无需每项目都有 SSE 与分布式 Trace。

## C12 部署、版本与兼容

阶段协议：[交付与运行协议](stages/delivery-and-operations.md)。

**适用**：交付运行代码；长期服务和在途任务要求更强兼容。

- 启动/退出/就绪、依赖配置、秘密注入、持久卷与运行角色清楚。
- 新旧代码、状态/事件/工具/消息格式和策略版本可协调演进。
- 回退知道能回什么、不能回什么；风险动作可停用，已有事实不抹除。

**证据**：可复现启动、优雅退出、旧任务恢复、迁移与回退演练。基础设施按容量与团队选择。

## C13 验证、值班与灾备

阶段协议：[交付与运行协议](stages/delivery-and-operations.md)。

**适用**：与项目承诺成比例；单机工具可以是简单恢复说明，业务服务要有相应运行保障。

- 测试覆盖关键不变量和失败窗口，区分单元/集成/合同/负载/恢复测试证据。
- 重要承诺关联实际入口、配置与运行断言，按 [证据工作流](evidence-workflow.md) 交接，不仅检查接口返回值。
- 值班材料能据症状定位、止损、恢复、验证和升级处理。
- 对承诺保存的数据明确 RPO/RTO、保留/备份/恢复范围，并实际验证恢复。

**证据**：执行结果、失败处理和未验证项；上线清单不会因为文件存在自动完成。

## C14 业务评测与受控改进

阶段协议：[交付与运行协议](stages/delivery-and-operations.md)。

**适用**：模型/策略会迭代；至少有代表性行为评估，不要求所有项目做训练或自优化平台。

- 分开执行成功和业务正确；结合人工修正、工具/业务结果与事故，不只看点赞。
- 样本有来源、允许用途、脱敏、期望与版本；候选评测绑定不可变配置。
- 评测工具隔离真实副作用；安全/质量/费用指标分别判断，避免平均分掩盖风险。
- 自动建议权限与生产生效权限分离；按风险设置批准、灰度、监控和回退。

**证据**：固定场景比较、独立安全断言、实际 sandbox 接线、发布门禁与回退。训练导出仅在有需求与合法用途时考虑。

## 怎样裁剪

对各项记录“本场景条件→要保证的行为→已有/拟用机制→证据→取舍”。例如本地只读摘要 CLI 可用单进程、文件配置和退出码，标明中断丢进度；跨天的共享审批流程可复用引擎持久任务，另补业务授权与外部动作账本。二者都不由表的数量决定水平。

图结构、协议、SLO 数值、状态名字和物理表数由项目产生。完整性指每个相关承诺被解释与落实，不指全部可选组件都被安装。
