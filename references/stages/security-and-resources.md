# 安全、资源、时间与成本协议

按项目风险选择控制。工具、插件、浏览器、模型和子任务都要从实际执行入口验证，不因运行在某个容器或使用某个 SDK 自动具备保障。

按 [共用适配规则](../engineering-workflow.md#逐条适配与项目记录) 选择本阶段条目。

## 进入阶段前

列出可信主体、资源/数据范围、模型和工具可达的执行能力、秘密来源、网络/文件出口、并发规模、时间与费用承诺。复用已有身份/配额/平台隔离，不机械增加审批、网关或集群。

## 工具是请求，执行权在后端

工具定义可以来自本地函数、动态插件、MCP、图节点或远程服务。注册/发现协议只说明如何找到与调用，不自动证明可信。

按能力声明：输入/输出、权限与资源范围、是否写入、风险、超时、重试条件、操作身份、可核实方式，以及需要时的审批/网络/数据政策。字段组织形式自由，检查运行路径确实使用它们。

可信身份、组织、账户等来自认证上下文；模型可以提出目标与参数，后端按业务规则校验。不要把“模型不要越权”当控制。参数合法仍可能业务非法，输出 schema 合法仍可能包含不可信指令。

拒绝与错误也要留下适当记录，但避免把敏感失败参数原样写日志。错误应可区分业务拒绝、基础设施异常和未知结果，不用空字符串伪装成功。

## 凭据与数据最小化

明确谁能读 prompt、工具参数、历史、事件、日志、记忆、产物和导出。只给模型与调用者任务需要的信息，秘密在工具/宿主层注入；密钥不写仓库、镜像、公开事件或模型上下文。

环境配置与秘密分开，隔离开发/测试/生产凭据、轮换与撤权。真正测试入口必须绑定测试资源，不能因为变量名字有 TEST 就断言隔离。日志脱敏、错误堆栈和对象存储访问同样需要检查。

## 网络、文件与执行环境

外部 URL、浏览器导航、下载、webhook 和代码执行按信任边界治理：

- 对公网访问工具，校验协议、目的地、解析后的 IP 与每次重定向，覆盖 loopback/private/link-local/metadata 等相关范围；处理 DNS 变化和 IPv6。需要访问内网的业务采用明确授权的范围，不能一刀切禁掉必要能力。
- 不将内部凭据自动转发给其他源；限制方法、请求/响应大小、时间和跳转；必要时在出口代理/网络层执行政策，不能只依赖模型传参验证。
- 代码/插件/浏览器的文件系统、子进程、网络、CPU、内存、运行时间与凭据边界明确。容器不是天然强隔离，宿主挂载、提权、socket、凭据继承会改变实际能力。
- 读写产物需防路径穿越与越权引用；临时工作区、进程和连接在完成、取消、异常、插件卸载时清理。保留必要诊断证据，不能提前清除未决操作身份。

用户已授权的合法能力按实际政策提供；出现 sandbox denial 先判断范围与原因，不能把反复扩大权限或绕过保护写成通用自动恢复策略。

## 并发、速率与预算

分别限制进入速率、在途数量、队列长度/年龄、单任务调用次数、上下文/输出规模、执行时长与费用。按用户、项目、租户、工具、provider 或系统选择实际需要的维度。

多副本总限额要由共享计量、服务配额或明确分配承担；进程内 semaphore 只限制本进程。崩溃后的容量回收、公平调度和高低优先级策略按场景设计。

预算声称“硬限制”时应能在动作前原子预留或提供等价最坏消耗上界，之后按实际 usage 结算，重复结果不会重复扣减。流中断/超时可能已计费，未知消耗不能直接归零。计量与结算失败要可修复。

估算值注明来源，金额用明确精度/币种规则。预算覆盖模型、工具、repair、fallback、子任务和重试；恢复或重开执行是否共享额度由业务意图决定，不能被无限重置。

达限行为需要产品合同：拒绝、排队、部分结果、降级或等待授权。不要自动提高用户额度、扩大模型权限或将无上限重试作为兜底。

## 超时、截止与剩余时间

对适用边界记录“计时起点/是否暂停 → 软告警还是硬截止 → 到期动作 → 负责执行者 → 传递与恢复规则”。不要复制一组统一秒数，也不要求异步任务的生命周期小于 HTTP 请求时长。

| 边界 | 到期应说明什么 |
|---|---|
| 入口请求 | 只停止等待响应，还是取消尚未受理的工作；已持久受理或已发出的外部动作怎样查询 |
| 排队 | 阈值仅触发告警，还是任务有效期已过；过期消息/延迟重试在领取时怎样拒绝 |
| 整体任务 | 按墙钟时间还是累计活跃时间；人工等待是否计入；到期后的结果、未决动作和资源处置 |
| 单次模型/工具/数据库调用 | 调用方停止等待不证明远端停止；结合结果确定性决定有限重试或核实 |
| 人工等待 | 批准的有效期、超时后通知/取消/移交规则；过期回复不得作用于新的等待点 |
| 执行者租约 | 表示所有权需重新裁决；不能把心跳丢失直接当业务失败或授权旧写者继续 |
| 观察连接 | 传输心跳、空闲与最长连接期限；依 [观察器合同](events-and-observability.md#长连接授权与保留期) 重连，不重新执行业务 |

先确定拥有整体时间预算的层。重试、repair、fallback、并行分支和子任务只获得其允许的剩余时间；调用超时通常受本次上限与剩余预算约束，并预留必要收尾时间。已无有效时间时不启动新动作；中断不能撤销在途副作用，仍按核实合同收敛。

跨进程恢复保存可解释的截止依据或累计消耗，不能每次重启重新计满。进程内耗时可用单调时钟；跨进程不能直接复用上一进程的单调时钟读数，持久截止要说明权威时钟、偏差容忍或引擎计时语义。活跃时间预算还要明确暂停和并行怎样计费时长。

各层超时顺序由调用/交接关系推导，并核对 SDK、数据库和平台默认值；拒绝为“整体延迟目标”机械缩短持续任务。用可控时钟验证排队、重试、等待、恢复和边界到期，避免长时间 sleep 测试。

## 应整理的产物

围绕实际主体、能力和资源给出门禁位置、数据/凭据流向及适用的隔离、清理、配额和时间合同；可用现有权限定义、配置与少量说明承载。单用户本地边界不必扩展为租户系统，无人工审批需求也不新增审批流程；仍处理工具真实可达的文件、网络和外部动作。硬限制要列出预留/拒绝/结算/恢复的真实拥有者；仅记录用量的控制注明为观测或软限制。

## 实现与验收

从真实工具/模型/后台入口验证越权拒绝、秘密隔离、路径/网络限制、撤权及取消后的清理。用可控时钟和并发请求检查预留、恢复不刷新预算、未知费用不归零、过期不启动新动作。

复用平台控制时验证配置和实际注入。测试适用边界即可；真实凭据、生产故障或外部写入不由本协议自动授权。
