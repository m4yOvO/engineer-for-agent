# 接口与身份协议

适用：函数、CLI、HTTP/RPC、消息、图/工作流和插件入口。输出是当前项目可实现的调用合同，不预设 HTTP 端点数量。

按 [共用适配规则](../engineering-workflow.md#逐条适配与项目记录) 选择本阶段条目。

## 进入阶段前

确定谁触发、什么算受理/完成、调用是否有界、断线是否继续、调用者怎样查询结果。核对现有认证、平台入口和协议版本；未知明确标记。

## 入口由调用者决定

| 场景 | 可行入口 | 要明确的语义 |
|---|---|---|
| 有界同步能力 | 函数、CLI、同步 RPC/HTTP | 调用截止、取消、输入输出、错误和部分结果 |
| 长时或需持久受理 | 异步命令、任务资源、引擎启动请求 | 接受成功意味着什么、如何取回身份与结果、重复提交 |
| 会话交互 | session/thread + turn/message | 会话与本次执行区别、并发输入、打断/排队、分支 |
| 图/工作流 | 引擎调用、外层业务命令 | thread/workflow/checkpoint 与业务身份映射、暂停/继续、查询 |
| 事件集成 | webhook、订阅、消息 | 来源认证、事件 ID、去重、迟到/乱序、确认和重新交付 |

需要时设计创建/读取/继续/取消/历史/产物访问，但不要强制六个 HTTP 端点。一个已有任务平台的 API 或 CLI 子命令也可以满足合同。

每项接口明确使用者与可信边界、输入/输出、错误和完成语义。按实际行为补充状态前置条件、持久受理边界、幂等范围/有效期、重试建议、分页/流式、数据可见性和兼容版本；无相应语义时不新增端点或字段。类型合法不等于业务授权；金额、资源范围等必须按业务取可信值或受权验证。

## 身份至少在语义上分清

| 身份 | 标识什么 | 常见混淆 |
|---|---|---|
| principal / scope | 当前用户、服务、组织或工作区权限范围 | 把请求 body 的 scope 当认证事实 |
| conversation / thread | 一段连续交互历史 | 把每次输入都当新会话，或把 thread ID 当访问凭据 |
| execution / turn / workflow | 一次执行或引擎定义的生命周期 | 因框架命名不同而强行映射为同一类 Run |
| node / task / invocation | 一项逻辑执行单元或工具调用 | 与业务动作的唯一性混为一谈 |
| attempt / delivery | 某次执行尝试或消息投递 | 重试换 attempt 合理，重试换业务身份可能重复操作 |
| operation / intent | 业务上允许发生的一次动作 | 仅用资源 ID，误合并两次合法的新操作 |
| branch / parent / lineage | 分叉、委派、重开与来源关联 | 覆盖旧历史，或泄露其他分支上下文 |

可复用同一个物理 ID，但必须解释为何语义和生命周期一致。只有需要的身份才设计字段。

API 幂等需指定作用域、规范化输入摘要、并发唯一性和保留期。同键同内容复用受理结果，同键异内容按契约拒绝；不要静默覆盖。新业务意图如何创建新身份也要有定义。业务工具幂等期限需覆盖可能的重试/恢复期；下游 key 过期后不能继续假定防重有效。

## 应整理的产物

按实际入口整理足以实现的调用合同和输入输出样例，直接引用现有类型、函数、CLI 帮助或协议定义。只展开适用的前置条件、受理/重复、查询、授权和兼容要求；需要分页或流式才设计对应协议，结果同步返回时无需另造查询接口。

区分客户端请求 ID、执行身份、模型工具调用关联 ID 和业务操作身份。响应丢失后的查询必须能使用调用者已知的稳定身份，不能仅返回一个尚未送达客户端的新 ID。

## 实现与验收

- 验证实际入口消费 schema、身份、权限及幂等约束，后台/管理/插件入口没有绕行。
- 同键同内容、同键异内容、跨主体/资源查询、响应丢失、未知/过期任务和无效状态有明确结果。
- 同步超时、持久受理和业务完成按合同区分；接口层不伪造下游结果。
- 接续 [数据](data-and-storage.md)、[状态](state-and-lifecycle.md) 和适用的 [队列](queue-and-execution.md) 协议。仅授权规划或审查时记录拟验证项，不执行变更。
