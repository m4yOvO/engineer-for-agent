# 工具调用记录与恢复协议

适用：模型、图节点、activity、插件或子 Agent 调用工具，尤其是跨进程恢复、昂贵重算或有外部副作用时。目标是保存足以解释和恢复的执行事实，并维持业务允许的重复语义。协议不要求固定表、状态名、框架或每个 token 落盘。

条目、产物和验收均按 [逐条适配规则](../engineering-workflow.md#逐条适配与项目记录) 选择；本阶段适用不代表所有子项都需要。

## 进入阶段前

确认实际工具入口、读写/副作用、执行架构和持久化拥有者、当前授权、取消/超时、下游防重与查询能力、结果保留及是否要回填模型上下文。没有模型参与的 activity 省略模型决策层；框架已提供持久 task/result 历史时直接映射其能力并核验启用配置。

模型重复提出请求、客户端重发、Worker 重投和远端实际执行是不同事件。业务允许的只读刷新可以重新调用；同一已完成 invocation 恢复通常复用原结果。不要仅凭工具名与参数相同永久合并合法新请求，也不能仅靠提示词要求模型“不要重复”。

## 需要关联的执行事实

下表是逻辑关系，可合并存储或引用引擎历史。Trace 可以辅助定位；采样、可丢或提前过期的 Trace 不能独自承担恢复依据。

| 事实 | 需要解释什么 | 关键关联与约束 |
|---|---|---|
| 模型决策/节点输出 | 哪次输入、版本和上下文产生了这批完整工具请求 | execution/branch、逻辑决策身份、模型请求/响应引用、有效代次、候选调用及顺序/依赖；重入复用已接受决策 |
| 工具调用 invocation | 哪个逻辑位置请求了什么工具及参数 | 稳定 invocation ID、所属决策/节点、provider call ID 的作用域、工具/schema 版本、规范化参数或受控引用及指纹 |
| 业务动作 operation | 哪个领域动作只允许发生一次 | 授权范围、实体/修订/目标/动作语义或等价稳定 key；跨 invocation/重开可能映射同一 operation |
| 执行尝试 attempt | 哪个执行者在何时实际尝试调用 | invocation/operation、attempt ID、执行权代次、开始/结束、下游请求/key、确定性、错误与实际消耗 |
| 结果或未决证据 | 有哪些已经可靠确认的返回/业务事实 | 原调用关联、结构化结果/错误或持久对象引用、下游引用/版本、校验与核实证据；未知不伪装失败 |
| 消费/上下文投影 | 哪些结果已供后续模型/节点消费 | 决策/调用到消息或图写入的关联、投影版本/水位、已接受的后续决策；可原子更新或从权威结果重建 |

参数哈希用于核对内容，不自动定义业务动作唯一性。provider call ID 用于该协议中的请求/结果配对；它可能只在某个响应内唯一。重试可有新 attempt，但不得借新 call ID 绕过同意图防重。模型发起重复请求时，后端按可信业务上下文解析 operation，不相信模型自报唯一键。

需要回放参数或结果时，单有摘要不够，应有受控载荷/不可变引用或可验证的引擎记录；设定访问权限、格式版本、保留和完整性。无法取回的数据明确成为恢复限制，不能为重建记录盲目重做写操作。记录可观察输入、工具请求和执行结果即可，不要求保存模型内部推理。

## 执行与提交顺序

以下定义逻辑提交边界；框架可一次提交多项，也可用可恢复的跨存储交接。先画出实际拥有者与失败窗口，再选机制。

1. **接受完整决策**。对模型返回的完整调用集合进行结构校验并关联逻辑决策。需要恢复的执行，在派发前保存足以重建该决策/调用的依据。流中的半截工具参数不自动成为可执行写请求；若采用增量执行协议，需独立定义完整性与授权边界。
2. **解析并检查调用**。依据当前身份/资源、工具能力与业务规则确定 operation；匹配参数指纹、批准内容及版本。恢复或复用结果仍检查当前权限、kill switch 和保留期。
3. **裁决已有事实与执行权**。已有完成结果则读取；已有未决尝试则核实；确实允许的新尝试才原子领取/预留相应资源。重复 Worker、重复决策和旧代次不能各自无条件执行。拒绝也形成可关联的错误结果。
4. **记录调用依据再执行**。在高影响写入前持久保存稳定意图与本次尝试依据，按已验证合同把同一 key 传给下游。数据库事务不跨外部长调用。即使只标记“准备发送”，崩溃也可能发生在真正发送后的下一瞬间，恢复不能仅据这个标记断言从未发送。
5. **保存结果或未决事实**。关联原 invocation/operation/attempt 保存可复用结果、权威错误或未知证据。先可靠保存恢复所需事实，再确认该工作单元完成。大结果先存完整对象再提交可验证引用；结果保存失败时不把外部操作重新生成一遍。
6. **回填并推进**。将已保存结果投影到正确模型消息/图任务位置，按调用身份去重；与“已消费”标记共同提交，或从权威结果确定性重建。随后在允许的结果集合上提交下一次模型/节点推进。ACK、容量释放与继续调度按 [状态](state-and-lifecycle.md) 和 [队列](queue-and-execution.md) 合同处理。

进程重启时首先查已接受的决策与调用事实，不能总是重新询问模型来“猜回”下一步。如果模型响应在任何持久记录之前丢失且尚未执行工具，重调模型可按策略接受，但可能增加成本或改变候选决策；需有单一有效代次/CAS 或引擎等价裁决，避免并发接受两套后续写动作。

## 同一业务意图与合法新动作

先定义“业务上只允许发生一次的是什么”。例如发布同一批准版本的报告、提交同一购买请求、给某审批决定执行一次资源变更。仅用实体 ID 可能挡住同一实体的合法多次动作；仅用随机 call_id 则可能放过同意图的重试。

可行身份包括业务命令 ID、实体 + 操作类型 + 业务修订、平台稳定 activity 身份。**如果某个引擎身份确实覆盖所需去重范围，可以使用它**；但若重开 workflow/Run 仍是同一业务意图，就必须把防重身份延续到新执行中。不要绝对禁止所有 run_id，也不要不加分析地用它。

操作合同应包含作用域、意图内容指纹、下游 key/引用、状态、结果、保留期限和冲突处理。逻辑操作唯一，尝试可以多条。命中缓存结果前仍检查访问权限，不能利用旧 key 读他人结果。

本地原子领取防同一入口并发，下游幂等/条件写防外部重复，独立核实处理响应丢失。没有普适的“加 unique 就实现 exactly-once”。若业务接受重复或存在可验证的自然幂等，不必强建同一款账本，但必须解释副作用含通知、审计、费用等是否也可接受。

## 未决结果、业务完成与持续对账

在可能产生高影响副作用之前，保存足以识别动作的受理依据；调用后记录已确认结果。不要长期持有数据库事务跨外部请求。

请求超时、连接断开、进程退出、网关 5xx 都不能单独证明外部未执行。核实结果至少区分：权威成功、权威拒绝/未执行、仍处理中、查询失败/暂不可见。最终一致系统中的一次“查不到”不等于权威不存在。

未知结果可以通过同 key 查询、webhook、对账任务、受控幂等重发或人工确认收敛；选择取决于下游合同。记录核实时间、证据、修改前后和操作者/系统来源。核实要有幂等/并发控制，并能独立于原执行任务运行；原任务已取消或失败不代表不再需要核实。

**已返回成功也可能需要继续核对。** 下游确认“已受理”、传输成功、工作流完成与业务最终完成可能是不同事实。为有异步结算、延迟失败、撤销或状态变化的动作定义终局性：哪个系统对哪项事实负责、哪些变化仍合法、何时停止自动核对。即时且最终的只读结果不必增加周期对账服务。

| 不一致 | 处理原则 |
|---|---|
| 本地未知，下游已有可靠结果 | 按原操作身份补齐事实，不换键重做 |
| 本地记为成功，下游仍处理中或确认失败 | 区分误判受理与后来变化；更新业务投影并追加核实/修正记录，不抹去当时执行历史 |
| 重复、乱序或迟到通知 | 核验来源、资源范围与操作关联；用下游版本/因果规则去重和裁决，接收时间较晚不等于事实较新 |
| 权威查询冲突、不可用或暂不可见 | 保留已确认事实和争议状态，限制核实次数/频率并告警或转人工；一次查不到不能反转成功 |

根据风险与下游协议选择事件通知、定期扫描、抽样核验或人工流程，设置范围/游标、截止、owner 和恢复办法。发现差异可修正读模型、发受控通知或启动另行授权的补偿；不能自动把“对账发现失败”变成重发原写操作。验证应包含已标成功后的变化、重复通知和旧通知晚到。

补偿是一个新的业务动作，也可能失败或需要授权。它不是回滚历史的时间机器，更不能在诊断模式里自动执行。不可撤销动作没有补偿方案时如实记录限制。

## 多工具、结果回填与恢复矩阵

一次决策中的每个调用有独立结果，不用“整批完成”一个布尔值覆盖部分成功。按依赖关系决定并行；失败/拒绝可作为结构化结果参与后续决策。哪些结果必须齐全、能否提前消费、何时停止其他调用由引擎/provider 合同决定，不强制所有系统同一 barrier。

为会话恢复构造合法的消息投影：工具结果与其原请求配对，避免孤立结果、重复 append 或调用关联丢失。顺序按原协议/图依赖恢复，而不是按响应到达时间臆造。上下文压缩可以引用持久结果，但不能丢掉尚未解决的调用和批准依据。

| 崩溃/重入时已有事实 | 恢复动作 | 不应发生 |
|---|---|---|
| 决策与调用已保存，尚无可靠完成结果 | 判定未开始还是在途/未知；有安全依据才执行原调用 | 重新生成另一批调用并换业务 key |
| A 已完成，B 未完成 | 复用 A；对 B 按自身事实执行、核实或移交 | 因批次不完整而重做 A |
| 外部可能成功，本地无结果 | 原 key/下游引用查询，或在已验证防重范围内受控重发 | 把超时/一次查不到直接当未执行 |
| 结果已持久化，模型消息/图投影未写 | 从原结果幂等补齐投影和消费关联 | 再调工具仅为得到相同返回 |
| 投影已写，消费标记未同步 | 用消息键/调用关联识别已有投影，修复标记或重建 | 重复添加结果导致下一轮协议损坏 |
| 部分投影后已接受后续决策 | 按已接受决策和剩余依赖接续；拒绝旧代次再次推进 | 同一逻辑位置生成两套有效后续动作 |
| 取消/租约失效后旧尝试迟到 | 记录真实效果证据，按所有权/版本规则归并；停止不允许的新动作 | 旧执行者覆盖新状态，或为保持取消外观丢弃已发生效果 |
| 结果载荷过期、损坏或版本不可读 | 给出明确恢复限制，查询权威事实或人工处理 | 用空结果伪造完成，或盲重做不可重复动作 |

已完成只读调用的历史结果与“现在再查一次”的新请求区分；新鲜度要求允许新 invocation，但不会把已批准写动作误当刷新。查询下游当前状态更新的是业务投影，保留当时原始调用结果与后续核实历史。

## 应整理的产物

按本项目的工具风险、恢复承诺和消费方式整理下列适用内容，可由已有协议/引擎记录承载。无需恢复且允许重新读取的只读调用可用输入输出、超时和错误合同；不因此强建持久账本。省略持久调用记录时仍需满足实际存在的业务防重、权限与审计要求。

- 工具能力合同：输入输出、副作用、可信权限来源、版本、取消/超时/重试、下游防重与查询、结果保留。
- 执行事实关系：在适用的决策、invocation、operation/attempt、结果及消费之间建立关联；无模型时省略模型层，标出合并/复用的引擎字段。
- 提交与恢复表：各边界谁持久保存、何时可 ACK/推进、重复和未知如何处置、哪些依赖未验证。
- 本次实现对应的故障验收与限制。复用项目设计和 schema，不要求六张表或独立工具网关。

## 实现与验收

沿真实调用入口验证协议被消费；不能只新增账本类或记录日志。优先选择本次承诺涉及的窗口：

1. 同一 invocation 重放、同业务意图的新 call ID、同 key 改参数、合法新修订，各自维持正确语义。
2. 并发领取和失去执行权后晚到：实际效果数/下游 key、持久结果、历史与资源归属可解释。
3. 决策提交后退出；A 完成 B 未完成时退出；保存结果后/回填前退出；回填后/标记前退出。
4. 下游生效后响应丢失、结果落盘失败、查询暂不可见或防重 key 过期：不盲重发，不伪造成功。
5. 多工具结果乱序、结构化失败、重复投影、恢复后下一模型输入配对正确；已接受下一决策不重复推进。
6. 当前撤权、取消、结果引用失效、旧工具 schema 与恢复后预算：保留事实并正确限制后续动作。

记录模型实际调用次数、每个工具/业务效果次数、原请求与结果关联、持久记录、剩余预算和恢复后的下一步。Fake 下游可证明本地协议，不能证明真实服务的防重期限、查询一致性或远程取消；参见 [证据工作流](../evidence-workflow.md)。
