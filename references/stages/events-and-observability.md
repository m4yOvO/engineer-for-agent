# 结果事件、订阅与可观测协议

适用：结果查询、历史、进度、流式观察、定位故障和告警。同步 CLI 可用终端输出与退出统计；只有产品需要可靠接续时才设计持久事件/游标。

条目、产物和验收均按 [逐条适配规则](../engineering-workflow.md#逐条适配与项目记录) 选择；本阶段适用不代表所有子项都需要。

## 进入阶段前

确定展示的事实源、结果/事件寿命、延迟与完整性承诺、受众和权限、并发观察者与传输限制。执行事实、恢复记录、UI 事件和 Trace 分工明确；展示失败不能重做业务来修复。

## 进度事件与观察器

按场景选 Polling、SSE、WebSocket、RPC stream、回调或终端输出。需要可靠接续时，保存事件或提供等价可重建事实，再通知观察端。

定义事件身份、顺序/因果范围、游标、分页/批量、重复处理、权限和保留。单任务有序不代表所有并行分支天然有全局时间顺序；可以采用单写序号、平台 offset 或可解释的因果关系。

历史转实时要处理订阅与查询间隙；通知是唤醒还是事实本体由所选平台决定。若只是唤醒，需要补偿读取防止丢通知后永远停滞。并发 `MAX(seq)+1` 需要真实协调，不是只靠字段名。

终态展示与最后事件一致；慢客户端有界缓冲和背压/断开恢复。可靠存档事件与临时 token chunk 可以分开，公开字段按授权投影。原生 EventSource 的认证/重连合同、代理缓冲和游标优先级需按实现核对；不要在 URL 暴露长期凭据。

### 长连接、授权与保留期

仅在持续订阅或可靠历史接续是产品能力时展开：

- 对连接建立速率、每个主体/任务的在途连接、最长连接时间和缓冲设置适用限制；多副本采用共享或明确分配的配额，异常断开能归还容量。
- 连接存活、业务进展、执行者租约是不同信号；按所用代理/传输配置心跳、空闲超时和重连退避，心跳不能证明任务健康。
- 明确令牌过期、权限撤销和数据可见范围变化怎样影响既有连接。采用与承诺相符的到期关闭、重新认证、周期校验或撤权通知；重新订阅仍需授权，不能靠旧游标保留访问权。
- 游标超出可读历史、日志代次改变或流被重建时，按契约显式返回历史不可接续，并提供获授权快照/结果或重新订阅办法。不能静默跳到最新却声称历史完整，更不能重启业务来补展示。
- 快照与后续事件需要同一可解释的水位/版本或等价同步办法，避免读取快照再订阅时遗漏变化；快照无法覆盖的历史缺口如实告知。

验证多实例重连、权限变化、历史过期、连接耗尽与慢消费者；复用平台已有机制即可，不要求增加 SSE 网关或某种消息产品。

## 观测与告警

按需使用结构化日志、指标、Trace、状态查询和审计。任务/会话/调用/分支/版本的关联让故障可解释；高基数字段适合日志/Trace，不应不加控制地成为指标标签。

关注用户可感知的完成率、等待时长、失败类别、模型/工具延迟、重试、未决动作、恢复次数、费用和业务结果。Counter 看增量/速率，Gauge 看当前值，分位数要有合理样本；不要把嵌套 Span 时长相加成总耗时。

CPU 低不表示业务健康。告警阈值来自 SLO 与实际基线，要有 owner、定位入口、处置步骤和恢复条件；能验证告警触达的范围如实记录。

## 应整理的产物

按结果交付方式选取输出字段与可见性、诊断信息及处置办法。需要历史接续时再展开事件/快照、身份/顺序、游标/保留和水位合同；有长连接时展开背压、断线和撤权。瞬时进度可以直接丢弃并重新查询当前状态，只要符合产品承诺；同步 CLI 可由输出/退出码及本地诊断承载，无需事件库。复用平台 offset、日志或状态重建可行，不要求 SSE 与独立网关。

## 实现与验收

覆盖历史与实时交接缺口、重复/乱序、最后事件和终态、历史过期、快照读取后更新、慢客户端、连接耗尽及既有连接撤权。验证观察器出错时业务效果数不增加、资源可回收，恢复只读展示不调用执行性 replay。

日志和 Trace 可定位到调用及版本；脱敏与访问策略生效，不能将采样 Trace 当作唯一业务账本。告警需要实际定位/恢复入口，阈值由基线与承诺确定。
