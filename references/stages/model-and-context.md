# 模型、上下文与记忆协议

适用：模型调用、结构化决策、多 provider、长上下文、记忆或检索。工具执行与结果的持久恢复由 [工具协议](tool-execution.md) 承担，本阶段说明怎样形成和消费模型输入输出。

## 进入阶段前

确认锁定的 provider/SDK、模型能力、允许的数据去向、结构化/流式协议、上下文来源、需要恢复的粒度和成本/质量目标。现成适配器是否真的被入口使用要有证据。

## 模型适配与调用合同

模型网关可以是一个适配模块，也可以是独立服务；不要求拆微服务。职责按需要包含 provider 路由、能力差异、超时/限流/熔断、结构校验、有界修复、usage 和版本记录。

内部协议要表达工具调用关联、结构化结果、拒绝、截断、取消、部分流与错误。不同 provider 的消息角色与并行工具支持可能不同，不能直接拼接一种协议用于全部模型。

fallback 改变的不只有价格，还包括工具/结构支持、数据传输目的地、区域、质量和安全策略。应使用允许的候选并经对应验证；故障时不能把敏感数据发送到未经批准的新供应商。repair 也计入预算，次数有界，保留适当的原/修后诊断信息。

## 上下文、记忆和 RAG

会话历史、执行恢复现场、可长期重用的记忆、外部检索结果分别建边界。

- 压缩/摘要服务于上下文容量，不能丢弃尚未完成的工具调用关联、审批依据、预算和关键业务事实。完整恢复数据可以存模型上下文之外。
- 记忆写入明确来源、用户/工作区范围、可信度、有效期、纠错、删除和冲突处理；模型推测不自动成为用户事实。
- 检索索引、缓存与输出同时遵守权限；授权应在合适的检索/取文路径生效，不能读出秘密后仅靠回答层过滤。
- 文档和工具结果是不可信输入，可能包含指令注入。引用来源不等于执行其命令；派生摘要与子 Agent 结果也不提升信任级别。
- 分支、fork、跨 Agent 共享记忆说明复制的是内容还是引用；权限变化、过期数据与删除如何传播。

## 应整理的产物

| 合同 | 需要明确 |
|---|---|
| 模型调用 | 输入消息/配置来源、实际模型和版本、超时/重试拥有者、usage/错误/取消、结构完成标志 |
| 结果消费 | 文本、工具请求、拒绝、截断和部分响应如何分类；下次输入从什么持久事实重建 |
| 上下文管理 | 预算、压缩触发、保留的未决调用/批准事实、来源与读取权限、丢失时处置 |
| 长期记忆/检索 | 谁可写/读、作用域、有效期、纠错/删除、索引/缓存同步与注入边界 |

只要求模型输出 schema 合法还不够；业务授权和副作用检查在模型之外。需要重新推理时形成可解释的新决策，保留原版本与费用，不用覆盖旧记录制造“唯一一次调用”的外观。

## 实现与验收

测试实际适配器的完整/部分/非法响应、拒绝、超时、工具关联、fallback 能力与数据去向。验证压缩后仍能接续未决调用、并行结果不串线、恢复不重复接受后续决策。

记忆/RAG 覆盖权限过滤、陈旧结果、恶意检索文本、跨分支共享和删除传播。质量、正确性与成本分别评估；fake 模型协议通过不能替代真实 provider 合同与代表样本质量验证。
