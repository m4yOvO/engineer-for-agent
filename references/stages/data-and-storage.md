# 数据、表与存储协议

适用：需要保存业务状态、结果、执行记录、恢复现场、历史或计量。纯函数可只有输入输出；需要保存文件不等于需要关系数据库。

## 进入阶段前

列出必须回答的查询、允许丢失/延迟的范围、并发写者、已有引擎数据、敏感性和保留要求。先确认谁拥有事实，再设计实体和物理表；不要从一套固定表名开始。

## 从问题反推记录

| 要回答的问题 | 逻辑记录 | 可选载体 |
|---|---|---|
| 现在在哪，结果是什么 | 执行状态、输出/错误、时限、版本 | 引擎查询、业务表、持久对象 |
| 发生过什么，能否解释 | 有关联和顺序/因果的历史 | 事件日志、工作流历史、追加文件 |
| 从哪里继续 | 足够恢复的现场及完成事实 | checkpointer、活动结果、序列化状态 |
| 哪次调用怎样 | 参数摘要/受控载荷、结果、错误、时长、尝试 | 调用记录、Trace、引擎任务历史 |
| 外部到底做了什么 | 操作身份、意图指纹、下游引用、已知/未知结果 | 业务账本或下游权威查询 |
| 花了多少、还能花多少 | usage、估算来源、预留/结算、限额 | 计量日志、预算服务、配额账本 |
| 谁批准或修改 | 可信 actor、动作、对象、理由、版本与时间 | 审计事件、审批记录 |
| 下次应改什么 | 反馈、业务结果、样本、候选及评测 | 文件数据集、平台评测、应用库 |

逻辑区分不要求物理分表。拆分依据是查询、并发、约束、保留时间、权限和写入成本；小规模可以合并，已有工作流记录可直接引用。不要无限制保存完整 prompt/response；受敏感性、允许用途和成本约束。

文件/SQLite 是否可用由并发、宿主持久性与恢复目标决定；明确锁、原子写、flush/fsync 或平台确认语义，换用另一数据库不自动保证正确。

## 设计表或等价结构时的整理顺序

1. **事实和关系**：区分业务实体、某次执行、逻辑动作、尝试、结果和展示投影；给主拥有者、关系基数、引用及删除语义。已有 checkpoint/activity 历史直接映射，避免第二个可独立改写的同类状态。
2. **字段和表示**：必要字段的含义、类型、可空、默认、单位/时区/精度、不可变性和 schema 版本。JSON/对象适合哪些可变载荷，哪些关键条件必须可以验证/索引。秘密不进入普通 payload。
3. **键和约束**：主键、业务唯一范围、外键或等价引用校验、状态/金额等业务约束。区分一个动作的一条事实与多次 attempt，区分同意图重试和合法新修订。数据库 NULL/大小写/归一化对唯一性的影响按所选引擎验证。
4. **查询和索引**：从用户查询、恢复扫描、派工领取、未决核实及清理路径推导过滤/排序/分页与索引；说明热点、稳定游标和并发更新。已有索引可以复用，不给所有字段盲加索引。
5. **一致性边界**：逐操作列出必须共同提交的记录、条件更新、冲突结果、锁/事务范围与异步投影。需要跨系统交接时转 [队列协议](queue-and-execution.md)；外部工具结果转 [工具协议](tool-execution.md)，本地事务不能回滚远程效果。
6. **演进和保留**：新旧代码读取、回填、索引创建和旧任务兼容；删除/归档不提前销毁恢复仍依赖的动作身份、结果或引用。备份与恢复检查覆盖关联对象；见 [交付](delivery-and-operations.md)。

多主体数据隔离可由行过滤、RLS、分库/schema、凭据或平台边界承担；按查询路径验证关联读取、后台任务、对象存储、缓存和向量检索，不强制每张表复制 org_id。

大文件、轨迹和结果可用受控对象引用；设计校验和、访问授权、过期/删除及备份恢复后的引用完整性。数据字典要能定位实际载荷，不能仅留一个无法恢复的摘要。

不要求所有字段/关系都物理分表。关系库可给 ER 图与 DDL/迁移；文件、KV、对象存储或引擎历史可给键空间、格式、原子操作和读写合同。未选引擎时给逻辑设计并标注实现选择，不能把伪 DDL 当已执行迁移。

## 数据保留与删除

区分短期 prompt、长期审计、业务事实、可重建缓存和备份；设计读取权限、加密、脱敏、归档与清除。追加历史的业务不可变性不等于敏感信息永远不能按政策删除；可用受控删除、脱敏或分离敏感载荷，保留必要审计。

删除/纠正需覆盖记忆、检索索引、产物、导出和副本；保留义务与用户删除请求冲突时，由项目明确政策，不由 Skill 编造通用期限。

## 应整理的产物

| 产物 | 必须能回答 |
|---|---|
| 数据字典/实体关系 | 字段是什么、属于谁、谁可写/读、哪个 ID 在重试后不变 |
| 约束和事务表 | 什么必须一起提交、并发谁胜出、失败后留下什么 |
| 查询与索引表 | 真实入口/后台任务怎样高效且正确找到事实 |
| 迁移与保留说明 | 旧数据/在途任务怎样继续，删什么、保留什么、怎样恢复 |

复用项目现有 schema、迁移和 ADR 即可；小项目可以合并成一页，不增加与需求无关的数据模型。

## 实现与验收

从实际启动路径验证使用的是目标持久适配器。以所选存储测试重开/重启、重复插入、并发更新、事务中途失败、引用失效、分页与清理边界。关系与删除约束在应用/存储的实际执行层生效，不能只出现在文档里。

关键验收包括：不能出现“状态已完成而结果丢失”；完成记录/命令不被重放覆盖；旧版本数据可读或明确停在可处理状态；承诺保留的结果在日志清理后仍可取回。测试范围依承诺，不把 SQLite 本地通过等同集群或断电保障。
