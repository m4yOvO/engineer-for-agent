# 把工程承诺追踪到交付证据

用于三个模式之间交接，或单独验收本次实现。复用已有 issue、ADR、测试报告或计划；小改动一段说明即可，不强制新目录、完整立项或额外审批。

## 一条承诺贯穿三个模式

| 模式 | 应留下的对应关系 | 不能提前认定 |
|---|---|---|
| /brainstorming | 项目承诺及适用能力 → 协议/数据/操作合同 → 拟承担组件 → 验收场景 | 设计中的机制已接通或已通过 |
| /check | 承诺 → 实际入口与配置 → 事实拥有者/依赖 → 证据层级与发现 | 名称、依赖、单条 happy path 证明全部分支 |
| /build | 本次承诺 → 实际改动与调用链 → 运行检查 → 结果和仍受限的条件 | stub、未接线适配器或只读代码检查等于运行保障 |

沿用项目任务编号或给需要追踪的承诺一个简短标识。能力 ID 可复用，但同一能力可能有多项不同承诺。记录“承诺/合同位置、入口到实现位置、验证环境与命令、关键断言及结果、未知或限制”；实现后的记录替换过时假设，保留设计变更理由。

例如“批准后发布报告不得重复”应能追到批准内容身份、实际发布入口、引擎重入边界与下游效果断言。仅看到 publish 函数或一个 checkpoint 配置不够。框架提供的能力注明配置与证据，不要求应用重写它。

## 纵向增量的完成条件

1. 代表性输入从用户实际入口到结果可走通，认证、持久适配器、策略、预算等适用依赖确实被注入并消费。
2. 正常路径与本次最关键失败窗口能解释结局；所需守卫发生在动作之前，不能只在结果里记录“已拦截”。
3. 本次改动影响的启动配置、迁移、旧任务兼容和处置说明与代码一致。尚未接入的真实依赖指出阻止了哪些承诺验证。

顺序按项目依赖安排，允许一个切片完成多项能力；无须先建完所有存储，也无须先运行全部模式。当前只授权规划或审查时到对应交付为止。

## 故障证据如何选

选择会破坏本次承诺的窗口，不要求每次全部执行。

| 窗口/刺激 | 除响应码外还要观察 |
|---|---|
| 受理后派工前退出 | 已确认工作是否仍可被找到并继续，是否重复受理 |
| 暂停/继续提交到一半或重复回复 | 等待身份、恢复现场、可达的下一步一致；旧执行者不覆盖新执行权 |
| 外部已生效但返回丢失 | 实际动作数/业务结果、稳定操作身份、未决记录及核实出口 |
| 下游迟到失败或旧通知晚到 | 业务投影按权威顺序收敛，既有历史保留，不触发重复写 |
| 截止、取消或恢复 | 不再开启不允许的动作；剩余时间/预算正确，已发生效果可解释 |
| 历史过期、撤权或慢观察器 | 展示明确重同步/拒绝，连接资源有界，业务执行不被重做 |

按适用性核对四类事实：**持久状态与历史、真实业务效果或受控 fake 的效果记录、资源/所有权释放、累计调用/费用/时间**。数量断言来自项目语义，不照搬示例步骤数、事件数或模型次数。

报告注明证据层级：静态检查、局部单元、隔离集成、真实依赖验收或生产观测。Fake 能证明调用约定与本地故障处理，不能证明真实下游的幂等保留期、计费或集群行为。失败注入先确认环境，不把测试授权扩展为真实生产故障演练。
