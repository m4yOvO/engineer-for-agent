# /check：按证据审查现有工程

## 建立证据范围

记录仓库/分支/提交或工作区状态、范围、配置环境及可访问材料。追踪真实入口→身份/输入→调度/引擎→模型/工具→状态/结果→调用者；图项目检查节点、边和 checkpointer，插件项目检查注册、拦截与卸载，托管平台检查实际连接与配置。

`rg` 用于找线索。搜不到 outbox/checkpoint 不证明缺少可靠派工/恢复；README、依赖包和字段名也不证明已接通。动态注册、生成代码或托管配置无法核验时说明证据缺口与核验办法。

## 重新核验项目适配

用 [能力索引](capability-map.md) 确认全面审查覆盖；局部审查注明未审范围。按 [逐条适配规则](engineering-workflow.md#逐条适配与项目记录) 从当前事实重判旧计划，无计划则建立本次最小映射。指出仍成立、条件变化或证据不足的选择及对相邻阶段的影响；调整建议留在报告中，默认不改项目文件或通用 Skill。

对适用条目追踪相关阶段的关键故障窗口，按 [证据工作流](evidence-workflow.md) 选取观测与复现。尤其核对框架锁定版本、实际持久化方式及各层重试配置。结论与适配选择分开：

| 结论 | 依据 |
|---|---|
| 已验证 | 实际接线与相关行为证据支持，注明证据层级 |
| 已发现缺陷 | 能说明触发条件、真实路径、违反的承诺及影响 |
| 部分覆盖 | 已有机制，但承诺或故障分支尚不完整 |
| 未知/未验证 | 材料不足或无法安全运行检查，附补证办法 |
| 不适用 | 当前无触发条件，附理由 |

测试缺失与行为缺陷分列；一个入口通过不代表所有节点、工具、租户和管理入口通过。表、图或文档缺失需结合实际交付合同及等价证据判断。

## 报告与验证边界

先列风险最大的确定发现，再列部分覆盖和未知。每项包括：

- ID、严重程度、置信度、关联项目条目/能力。
- 文件行号、调用路径、配置或运行证据；具体触发、后果及范围。
- 最小修复、可复用机制、替代方案与代价；复现/反证和修复后的验收。

严重程度按影响区分：P0 紧急业务/数据/越权风险；P1 当前用法下的重大缺陷；P2 常规可靠性或交付缺口；P3 维护建议。结合频率、范围及补偿措施，不按关键词或未验证推断升级；没有生产观测不能宣称事故正在发生。

报告合并适配记录、证据、已有保障、实际检查和未运行原因。默认不打总分；用户需要时说明分母、权重，未知不算通过。

复现前核对测试实际注入的适配器、凭据来源与出口，不读取或输出真实密钥。默认只运行隔离检查；不在真实系统杀 Worker、重放写操作、批量恢复或回滚。发现紧急问题给出止损建议及证据，实施遵循入口中的授权边界。
