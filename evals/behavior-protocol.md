# 隔离行为验证

本目录验证 Skill 怎样规划、审查和构建。夹具刻意包含不完善实现，只能复制到临时目录评估，不能作为生产模板。没有真实账户、网络端点、模型调用或业务写入。

## 执行

1. 冻结本次 Skill 文件版本/摘要，复制 [fixtures/](fixtures/) 中的项目到独立临时工作区。保留原件并计算基线文件摘要。
2. 给独立执行者 Skill 的入口/参考文件、相应项目材料和其中的用户请求。不提供评分标准、缺陷清单或预期修改；不要让它读取其他案例、旧报告和验收器。
3. 规划与审查结果写到项目外的报告路径；构建只修改指定项目副本。限制为本地文件与标准库，不调用网络、真实 provider、浏览器、部署或版本库推送。
4. 保存实际输出与文件变更，核对规划/审查的项目摘要没有变化；构建运行执行者自己的检查，再由维护者执行 [assess_build.py](assess_build.py) 检查运行行为。
5. 逐项人工判断设计与发现是否有证据、是否适配架构、是否遵守模式。记录失败、未覆盖项和测试局限；不能用关键词匹配代替判断。

只有存在独立执行输出才能称为行为验证；作者阅读指令、语法检查和空夹具测试属于静态检查。执行者依照隔离约定工作不等于验证了操作系统级安全沙箱。

## 可重复的构建验收

在独立执行者完成 B01 后运行：

```sh
python3 evals/assess_build.py /absolute/path/to/isolated/build_wait
```

验收器执行指定目录中的 service.py，仅对可信、已检查的隔离夹具副本使用。它不安装依赖、不调用网络，数据库位于临时目录。先在原始夹具运行应出现预期失败，用以确认测试能区分不完善实现；原始失败不是 Skill 行为失败。
