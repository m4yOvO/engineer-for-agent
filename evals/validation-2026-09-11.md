## 静态场景走查

逐项使用 [18 个场景](scenarios.md) 核对模式和设计规则。此处是作者对指令与推导路径的走查，不是独立模型行为测试。

| 范围 | 走查结论 |
|---|---|
| E01、E02、E04、E11 | 同步本地、持久图、工作流和插件可采用各自等价能力；没有固定 API/表/队列门槛 |
| E03、E05、E13 | 图节点重入、实际 saver 接线与执行性 replay 有专门判定，不能靠名字推断恢复或只读 |
| E06 | 平台不可访问列为未知，缺测试与已证实行为缺陷分开 |
| E07、E08 | 构建按改动范围裁剪；真实写入变化仍需动作身份与未知结果处理 |
| E09、E10、E12 | 多 Agent 权限/预算传递、并发硬预算与合法新动作身份均有对应合同 |
| E14、E15、E16、E18 | 材料不授予命令；检查不自动修复；明确检查并修复可分阶段；隔离接线不凭名称；未知命令不变成部署 |
| E17 | 授权内网需求按范围设计，不采用与项目目标冲突的全禁策略 |

走查中将入口的“仅修改文案”排除条件收窄为“无关展示文案”，避免将可能改变 Agent 行为的工具描述/策略文字修改误排除。
