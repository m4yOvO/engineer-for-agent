# 实时演练助手工程计划

本次采用 `/brainstorming`，推荐保留项目已选的 **Python 状态图执行层、本地 IPC、现有窗口与轮次 ID**，在桌面应用生命周期内运行单个 Python 执行宿主，以窗口为串行控制边界，复用现有取消令牌与图调度适配器。会话内容、当前图状态和展示快照全部仅存内存；用户明确选择的总结通过独立导出入口写入指定 Markdown 文件。该方案直接对应双窗口、随时打断、当前状态重连和退出即清除的产品承诺。

本报告采用最终 Skill 快照，已读取 `references/engineering-workflow.md` 当前“逐条适配与项目记录”首段，保留项目明确的技术选择、产物形式与交接要求。报告是实际工程规划，不包含业务实现、迁移或部署。

## 1. 已知事实、假设与交付边界

输入仅来自指定 [项目需求](../../fixtures/item_adaptation/planning.md)。指定项目目前只有这份需求材料，没有可以核验的入口代码、依赖锁文件、运行配置或测试。下文组件名、接口名和实现位置均为拟定，接手开发者应映射到真实目录；不能据此认定已有能力已经接通。

| 类别 | 项目事实或规划决定 | 工程含义 |
|---|---|---|
| 明确约束 | 一个操作系统用户，最多两个练习窗口；每窗口最多一个当前轮次 | 不引入账号/租户系统；窗口间隔离，同时处理旧任务尚未结束的情况 |
| 明确约束 | Python 状态图、本地 IPC；转写归整→只读检索→模型反馈→展示 | 不替换为手写 Agent 循环、HTTP 服务或远程调度平台 |
| 明确约束 | 会话可能持续 45 分钟 | 支持长会话、资源有界；45 分钟不是自动结束会话的截止线 |
| 明确约束 | 可立即打断开始新轮，旧文本与迟到结果不能进入新轮 | 取消请求之外必须有提交时的轮次校验；采集、检索、模型、图归并和 UI 都携带轮次关联 |
| 明确约束 | 重连仅看当前轮状态与已生成内容 | 当前完整快照即可，不存进度事件历史、不执行图回放补 UI |
| 明确约束 | 内容只驻内存，退出/崩溃不恢复，会话结束释放 | 禁止会话数据库、磁盘 checkpoint、内容日志/Trace、缓存及隐式恢复文件 |
| 明确约束 | 只有显式导出选中的总结可以落盘，失败保留旧文件完整 | 导出能力由宿主 UI 授权，文件原子提交；模型没有文件写权限 |
| 材料陈述，待验证 | 已有 IPC 路由、取消令牌、图调度和模型流式适配草案 | 优先集成和补合同，验收必须从实际桌面入口穿透到适配器 |
| 工作假设 | 同一桌面应用实例管理两个窗口，并连接同一 Python 宿主 | 可用进程内串行提交与总资源控制；若实为每窗口各起宿主，先调整应用启动接线，再核对共享额度和导出锁，不能声称进程内锁覆盖多进程 |
| 待确认但不阻塞规划 | 图框架/SDK 版本、目标桌面系统、IPC 传输、模型供应商、转写数据来源 | 第一增量核实；保留状态图与 IPC 选择，使用适配器封装具体语义 |

当前不承诺进程重启恢复、离线历史、跨窗口共享会话、云端协作、精确远端取消或精确费用上限。云端协作尚未决定，不能预先加持久队列或同步存储。执行成功指当前轮得到完整、合规的反馈并可展示；反馈质量另用固定演讲样例评估，不能只看图运行成功。

## 2. 结构、职责和代表性路径

拟定调用关系：

```text
窗口 UI / 转写输入
  → 现有 IPC 路由与窗口绑定
  → WindowController（每窗口串行控制、当前轮次裁决）
  → 现有图调度适配器 → Python 状态图
       归整 → 只读资料检索 → 模型反馈流 → 完成
                  ↓ 所有异步提交均检查轮次身份
       内存图状态 / 当前输出 → 当前快照 → IPC → 原窗口

UI 选择总结 + 保存对话框 + 覆盖选择
  → 独立 ExportService → 原子提交指定 Markdown 文件
```

| 拟承担组件 | 具体实现职责 | 事实及边界 |
|---|---|---|
| 桌面宿主与 IPC 层 | 创建/销毁窗口绑定，协议握手，输入大小校验，可信来源识别，保存对话框与导出授权 | 请求中的 `window_id` 仅用于关联，不能自行授予访问其他窗口的能力 |
| `WindowController` | 串行处理开始新轮、取消、接收当前轮提交、结束会话；分配代次，管理任务句柄与有界调度 | 拥有“哪个轮次是当前轮”的唯一事实；不再实现一套可任意改写的图步骤状态机 |
| 图调度适配器与状态图 | 执行既定节点、条件边、异常路由和取消检查；输出只能通过受控提交入口归并 | 图拥有节点位置、输入与节点结果；公开进度是该事实的投影 |
| 只读检索适配器 | 内置资料范围内检索、数量与字节上限、返回来源标识、取消/超时 | 共享的只有不可变内置资料；查询、检索命中和派生缓存属于具体轮次内存 |
| 模型适配器 | 流式协议转换、请求关联、内容完成判断、超时、取消请求、usage 分类 | 唯一允许的会话网络出口；目的地来自用户配置与同意，密钥从操作系统凭据库取用 |
| 内存状态与快照投影 | 当前图 channels、输出、错误类别、版本、资源计数及订阅 | 不落盘、不跨启动读取；展示只能读取获授权窗口 |
| `ExportService` | 固定选中内容，校验目标授权与覆盖选择，原子写入、防并发覆盖、结果确认 | 唯一内容持久化能力；不注册成模型可调用的工具 |
| 诊断适配器 | 允许字段白名单、计数/时长/错误类别、统一异常转换 | 禁止载荷、原始异常字符串、prompt、路径、凭据及内容哈希进入诊断 |

正常路径：窗口 A 提交新轮 T1；控制器完成校验、创建图任务并提交内存受理事实后确认。归整、检索及模型分别提交带 T1 代次的结果，状态先更新再通知 UI；完整结果与完成位置一起可见。窗口 B 有自己的控制器和图状态，不能读取或复用 A 的文本。

打断路径：A 的 T1 模型仍在返回时，用户开始 T2。控制器在同一串行边界切换当前代次、撤销 T1 提交权、清空展示并安装 T2 的独立状态，然后向旧令牌和模型适配器发取消。T1 的所有后续文本、检索结果和完成回调在提交入口被拒绝；旧清理仅能释放自己的任务/调用票据，不能删除 T2 的状态或释放 T2 的容量。T2 可以立即成为当前轮；若旧请求尚占用有界资源，显示“等待模型资源”，不得无限增开调用。

失败路径：模型连接中断且已有部分输出时，当前轮保留内存中的已生成文本并标为不完整，停止后续自动生成，返回可解释错误。用户可保留查看或开启新轮。重连只读该快照；执行宿主崩溃则返回会话已结束并清空前端旧视图，不恢复或重传旧转写。

## 3. IPC、身份和入口合同

复用前端 `window_id`、`turn_id`。宿主另提供每次 Python 启动的新 `runtime_epoch`、窗口内每次会话的 `session_id` 及后端递增 `generation`，用于阻断重连、ID 复用和旧回调，不替换前端已有身份。可信窗口绑定来自桌面宿主及现有 IPC 对端验证，不从模型内容或任意请求体派生。若使用本地 socket，应限制对端与访问权限；同操作系统用户边界不等于任意本机进程都可读取内容。

所有异步工作固定携带 `{runtime_epoch, window_id, session_id, turn_id, generation, invocation_id, attempt_id}` 中适用字段。轮次身份描述生命周期，`invocation_id` 表示图中一次逻辑调用，`attempt_id` 表示一次尝试。只读调用不新增业务写操作账本。

| 拟 IPC 操作 | 输入与前置条件 | 返回、重复与失败语义 |
|---|---|---|
| `open_session` / 握手 | 可信窗口绑定、协议版本 | 返回当前启动代次、会话身份、能力；重复握手读取现有会话，不隐式重建当前轮；版本不兼容拒绝 |
| `start_turn` | 窗口/会话、前端新 `turn_id`、稳定 `command_id`、规范化输入、预期当前代次 | 校验输入后串行安装新轮并创建受控图任务，返回新代次与快照；仅承诺本进程内受理，不承诺崩溃后继续 |
| `append_transcript`（实时转写入口） | 当前轮、代次、`segment_id`、修订号、文本/结束标记 | 同片段同修订相同内容去重；同修订内容冲突拒绝，旧修订/旧轮拒绝；不得把迟到文本重新标注到“当前轮” |
| `finish_input` | 当前轮/代次、输入结束序号 | 固定本轮输入版本并推进归整；重复结束不再调图；结束后的迟到转写拒绝。若现有输入一次性提交，此操作可合并进 `start_turn` |
| `cancel_turn` | 明确目标轮次/代次 | 串行撤销目标轮提交权，确认本地停止未来推进；重复返回同一结局，旧轮请求不得取消新轮。远端取消状态另列 |
| `observe_current` | 可信窗口绑定、会话/启动代次 | 原子订阅并返回当前完整快照；没有当前轮返回空状态，启动代次不同返回 `session_ended`；不触发模型/检索 |
| `end_session` / 窗口关闭 | 绑定窗口和会话 | 撤销该会话所有提交权，取消任务、关闭订阅、清理内容和缓存；重复幂等。另一窗口不受影响 |
| `export_summary` | 原窗口、选中总结及版本、一次性用户操作、宿主保存目标能力、覆盖模式 | 独立导出合同见第 6 节；未经用户选择的文本、模型提供的路径和后台自动导出一律拒绝 |

`start_turn` 的响应丢失后，客户端先凭已有窗口/轮次身份查询当前快照。同 `command_id`、同内容只返回原受理结果，不重复启动；同键异内容返回 `command_conflict`。去重只在当前会话内，保存必要命令身份和内存内容摘要；不记录到磁盘，容量耗尽时拒绝新增而不是悄悄淘汰防重所需身份。旧轮次号在会话内不复用；旧命令不能以重试名义变成新轮。双击或乱序新轮通过 `expected_generation` 条件裁决，落败方收到 `stale_generation` 并读取快照。

若任务创建在受理原子边界内失败，返回 `start_failed` 并给出已撤销旧轮后的明确空/失败状态，不声称新轮已启动，不自动恢复旧轮。成功确认前，图任务句柄和当前内存状态必须一致可查；确认丢失不应造成第二次执行。对端超时只代表没收到响应，不自动取消已受理的当前轮。

错误使用稳定类别，例如 `invalid_input`、`window_scope_denied`、`stale_generation`、`session_ended`、`capacity_limited`、`model_timeout`、`model_refused`、`partial_output`、`export_conflict`、`export_failed_before_commit`。用户消息由类别映射，原始第三方异常不得进入日志或 UI 调试详情。

## 4. 内存模型、图控制和并发边界

拟定最小逻辑结构，可放入现有适配器和运行时模块，不要求关系表、DDL、索引或新数据库：

| 内存事实 | 关键字段/引用 | 拥有者及删除时点 |
|---|---|---|
| 应用运行时 | 随机启动代次、窗口绑定表、进程资源池、只读资料版本 | 桌面/Python 宿主；退出全部消失 |
| 窗口会话 | 会话 ID、当前轮引用、递增代次、命令防重记录、会话累计调用计数 | 窗口控制器；结束会话清除，不能引用另一窗口 |
| 当前轮 | 轮次身份、转写版本、图 channels、节点位置、规范化文本、来源、已生成输出、完成/错误类别、快照修订 | 图运行实例；被新轮替换时断开内容引用，正常当前轮可供本会话查看/导出 |
| 调用尝试 | 原轮身份、逻辑调用/尝试 ID、取消令牌、任务/传输句柄、时间、资源票据、usage 已知/未知 | 调用适配器；调用退出即清理。取消后仅保留收尾必要的非内容信息，不长期保存旧响应 |
| 当前快照 | 本轮身份、单调递增 `revision`、阶段、已生成全文、完整性、可展示错误 | 图当前状态的只读投影；不允许 UI 改写权威状态 |
| 导出准备 | 明确选中内容的不可变内存副本、摘要版本、目标能力、覆盖授权、操作 ID | 导出服务；成功、放弃或失败后释放；会话结束未提交则中止并清理 |

节点推荐保持现有串行依赖，不为了套用框架增加并行分支。图实现进度可呈现“接收转写、归整、检索、生成反馈、完成”，取消/失败/部分结果是该轮控制和执行结局的投影。无需固定六状态、持久暂停/继续、恢复位置或持久历史。若框架执行需要 saver，只能采用已核实纯内存且可按会话释放的实现；优先关闭 checkpoint/历史收集。内存 saver 并非默认需要，禁止任何磁盘 saver 或托管 Trace 的自动配置。

关键提交规则：在每窗口的同一串行区内验证当前轮、代次、未撤销、未终结与预期调用，然后一起归并节点结果、输出完整性和快照版本；完成时结果与完成标志必须同一原子更新可见。串行区不能持有跨模型调用的锁。后台线程结果先投递到所属控制器，不能直接改共享图字典；若图框架 reducer 会先写状态，守卫必须进入该写入路径，不能仅在 UI 丢弃旧事件。

概念伪代码（合同说明，不是项目实现）：

```text
开始新轮：
  串行校验绑定、输入、命令重复与 expected_generation
  固定新的 generation，撤销旧轮提交权，安装空的新图状态
  创建有界调度中的图任务并保存其句柄；生成当前快照
  离开串行区后取消旧任务；返回新轮受理结果

接收节点/模型结果：
  在窗口串行区核对完整轮次身份、调用身份和未终结条件
  不匹配：丢弃内容，只增加无内容的迟到计数
  匹配：校验结果、归并到该图状态、推进 revision、通知快照订阅

旧任务 finally：
  仅按自身唯一票据释放一次资源，清理自己的句柄
  不按 window_id 批量清除当前轮或覆盖当前状态
```

取消与完成在串行提交边界裁决：完成先提交则本轮可显示完整结果；取消先撤销则迟到完成不能转成成功。开始新轮无论哪个先发生，都换新代次且清空旧显示。实际图前进位置由框架维护，应用代次仅管理会话控制与合法提交范围。

本地异步调度仍需有交接责任。IPC→控制器→图任务的内存句柄必须可定位、可取消；资源队列若需要，仅保留每窗口一个最新待运行当前轮，替换时删除旧待办。领取前再次核对当前身份及截止。不会新增 Broker、Outbox、租约、死信或跨进程恢复扫描器。进程退出允许丢弃全部工作，并向前端明确会话结束。

## 5. 检索、模型、时间与资源

| 能力 | 输入/输出与可信范围 | 取消、重试和结果处置 |
|---|---|---|
| 转写归整 | 仅本轮已接受的文本片段与版本；输出规范化文本及质量提示 | 有界 CPU/输入长度；取消后禁止归并；不增加云端转写服务，来源未明确时沿用现有输入边界 |
| 内置检索 | 本轮查询、固定只读资料集合；返回有限条数、字节数、来源及资料版本 | 默认一次读取；已确认瞬时只读错误可由图节点层作有限重试。未取到资料可明确降级为无资料反馈，不能伪造引用 |
| 模型反馈 | 当前轮的必要文本和必要资料片段、静态反馈约束；返回有序文本块、结束原因、usage | 当前适配器统一完整/拒绝/截断/超时/取消/部分流语义；完整结束才可标完成，收到 EOF 不自动等于成功 |
| Markdown 导出 | 用户选中的总结固定版本和目标能力 | 非模型工具；不自动重试覆盖，提交与未知确认见第 6 节 |

前端采集回调在注册时捕获轮次身份，不在回调到达时读取“当前轮”再标记。模型流也始终绑定发起调用的轮次和 attempt，重复块按适配器序号或已消费位置去重；异常缺块导致不完整标志，不靠重复追加凑全文。图请求中的动态工具能力仅限需求范围，检索文本即使包含“导出、切换供应商、读取其他窗口”等内容，也只是数据，不能改变实际可调用能力。

每个新轮默认只使用本轮输入与内置资料，不继承上一轮转写、检索缓存或模型消息。45 分钟会话不等于向模型持续追加 45 分钟历史。上下文构造在调用前按输入大小、资料条数、模型上下文和输出上限检查；必要时对当前轮做内存压缩，标识压缩结果，超限则要求用户缩短本轮输入。没有长期记忆、内容向量写入、反馈数据库或训练采集。

模型适配器只访问用户配置并同意的目标服务，凭据在宿主调用层读取，不进入图状态、提示词或 IPC 内容。重定向和 fallback 不能跳到未经同意的服务或转发凭据；当前版本不默认启用备用供应商。撤销服务同意时停止新调用、取消在途请求并撤销结果提交；既已发送的内容不能承诺撤回。供应商数据保留条款与远端取消能力属于待核验事实，本次不联网确认。

重试唯一拥有者设为图节点/调用策略层，SDK、IPC 和外部循环的隐式自动重试关闭或纳入同一个明确上限。默认模型请求不在流中断后自动重试，避免重复计费和混接文本。仅对能证明未发出的瞬时错误，可在剩余时间与次数内重试；用户重新生成是新轮，不伪装续传。模型超时或取消可能仍在远端执行，usage 缺失记录为“未知”，不能记零或声称费用退回。

| 资源/时间边界 | 拟执行合同与拥有者 | 到期/达限行为 |
|---|---|---|
| 会话时长 | 生命周期从创建到用户结束；单调时钟统计，不以 45 分钟硬截止 | 以至少 45 分钟双窗口场景验证有界资源；不因一次 IPC 空闲断开销毁会话 |
| 当前轮截止 | 从本轮受理起计入资源等待与重试；具体阈值由样机与模型延迟基线确定后写配置 | 控制器到期撤销提交权、停止后续节点、取消在途调用，保留当前部分输出并解释 |
| 单次模型/工具 | 传递 `min(单次上限, 轮次剩余时间-收尾余量)`；流首包、流空闲与整体上限分开 | 适配器超时关闭本地等待，报告确定性；未获有效时间不启动新调用 |
| IPC 请求/订阅 | 请求等待与图生命周期分开；连接超时只清订阅 | 重连取当前快照，不重放业务；关闭窗口/显式结束才撤销会话 |

资源上限涵盖已取消但本地尚在收尾的任务。两个窗口调度应公平，任一窗口反复打断不能产生无限待办，也不能让另一窗口永久饥饿。只有已核实远端限制时才能声称约束了供应商实际并发；本地信号量本身不提供该保证。

## 6. 唯一持久化通道：Markdown 导出

导出保持 Markdown 形式。用户在原窗口选择可见总结或其中指定部分，宿主固定该版本的不可变内存副本；完整性不足的总结应显示“未完成”，由用户明确选择是否导出。文件内容只包含用户选中的总结和界面已展示且获选的必要标题，不自动追加转写、完整检索资料、prompt、日志或其他轮次内容。

保存对话框提供两个明确选择：默认“另存为/创建新文件”；目标已存在时显示明确目标并由用户选择“覆盖此文件”或改名。没有覆盖同意不得改动旧文件。重新选择目标、内容或覆盖模式产生新的导出授权；后台重试不能复用授权写另一个路径。

路径授权由桌面保存对话框产生短期内存能力，绑定选中内容版本、目标父目录、文件名和覆盖模式；Python 导出入口不能把模型或任意 IPC 字符串当成路径授权。允许写用户通过对话框选择且操作系统授权的普通 `.md` 文件，不强制局限于项目目录；拒绝路径穿越、设备/FIFO、目录和受保护应用数据路径。默认拒绝符号链接/别名目标，要求重新选择实际普通文件；父目录打开后通过稳定目录句柄和无跟随操作防目录替换。仅调用 `resolve()` 后直接按字符串打开不足以防竞态。具体系统的句柄、沙箱授权及同目录原子操作需在目标平台核验。

同一应用两个窗口导出到同一目标时，用稳定父目录身份加文件名作为锁范围，串行处理写入。覆盖授权绑定用户确认时的目标版本/文件身份；第二个操作发现目标已变化则返回 `export_conflict`，再次展示覆盖选择，不能静默覆盖另一个窗口刚导出的内容。默认创建模式应使用平台支持的原子“不覆盖发布”操作，不能用“先检查不存在，再普通 replace”代替。

拟写入流程：

1. 从原窗口读取授权的选中内容并固定 UTF-8 Markdown 字节；在任何写入前完成内容大小、目标路径、覆盖选择、目录与普通文件检查。
2. 在选定目标的同一目录以不可预测名字、独占创建、最小权限建立临时文件。该临时文件只属于此次已授权导出，只含获选总结，不能成为普通会话缓存。
3. 完整写入全部字节，检查写入长度，flush 并同步临时文件；此前发生磁盘满、权限失效、取消或其他错误，只删除临时文件，原目标完全不变。
4. 复核同一目标、覆盖授权及版本冲突，用已核验的同文件系统原子发布/替换操作提交。**原子替换是唯一提交点**；绝不以 truncate、先删旧文件、跨文件系统复制或分段覆盖目标降级。
5. 提交成功后仅报告“已保存”；返回丢失时同操作 ID 在会话内复用提交结果，不再次写入。若提交响应或其后目录同步出现不确定性，报告“保存结果待确认”，检查目标是否为预期完整文件，不将它当作可盲重试的写入失败，更不盲目回滚覆盖后续文件。
6. 清理导出准备内存和仍存在的临时句柄；失败前提交场景保留旧文件完整。取消在提交前生效；提交后不能承诺取消已写入文件。若会话结束与导出竞争，同一门禁先裁决：未提交则撤销，已提交则按已明确授权的导出完成。

用户所要求的“写入失败保留旧完整文件”必须通过目标系统文件能力实现：确定性失败发生在提交前时旧文件逐字节不变；提交原子性保证观察到旧完整文件或新完整文件，不出现半文件。对于不提供所需原子替换/不覆盖能力的网络盘或特殊文件系统，直接拒绝该位置并提示另选路径，不能降低保证。断电持久性、外部进程同时改同一目标的强条件替换语义需单独核验，不从 `rename` 名称推断；无法安全维持覆盖版本条件的环境先限制为创建新文件。这里的“待确认”专指提交边界不确定，不可用于掩盖确定性写入错误。

导出产生的临时文件是唯一获授权持久化操作中的中间产物。正常失败/取消必须清理；进程在临时写入后崩溃可能留下仅含已获选总结的残留，不能声称绝无残留。优先使用目标平台可发布的匿名临时文件；若只能命名临时文件，需验证崩溃残留处置，并在同一授权目录内清理可核实由本应用创建的残留，不能扫描任意目录或删除只因名字相似的文件。不会持久保存导出历史、整个会话或备份副本来完成该流程。

## 7. 隐私、观察与清理

隐私是首个增量即执行的合同。图/SDK 调试、自动 tracing、遥测插件、会话 checkpoint、HTTP 请求转储、异常对象序列化、文件日志、内容缓存、前端 localStorage/IndexedDB、页面恢复快照和崩溃附件都需检查真实启动配置。只写“开启脱敏”不足以满足要求，默认不传入内容，采用诊断字段白名单并在异常入口统一转换。测试使用合成标记文本检查应用受控目录、日志、临时目录和诊断输出，捕获前端及后端文件写入路径；未显式导出时不得出现任何内容标记。

内置资料文件本身是只读输入；从资料提取的查询结果和模型上下文不再落盘。跨会话共享的仅为静态程序、只读内置索引和非内容配置。凭据使用现有操作系统凭据库；不导出、不打印，也不为了调试复制到文件。

会话结束和窗口关闭时：撤销所有代次→取消图/调用→移除订阅、采集回调和计时器→清除前后端状态、图 channels、内存缓存和取消任务引用→释放该会话资源。窗口 B 保持运行。执行宿主退出时不序列化状态；宿主失联后 UI 清空旧内容并显示练习已结束，禁止启动新 Python 进程后把前端旧快照当恢复输入自动提交。

Python/浏览器运行时释放引用不等于安全擦除每一份底层内存，也不能仅靠应用代码排除操作系统交换区、休眠映像或系统崩溃转储。实现必须禁止应用层内容落盘及内容型崩溃附件；目标平台若把“只在内存”解释为连上述操作系统持久介质也绝对排除，需要核实锁页、转储/交换策略或受支持平台约束，再给出可满足的边界。此项属于明确未核验的运行条件，不允许偷偷放宽隐私承诺。

进度使用现有 IPC 当前快照通道。每份快照含当前轮身份、`revision`、阶段、已生成全文、完整性与安全错误类别。注册观察者、读取快照及确定起始修订在同一窗口串行边界完成；后续只发送比该修订新的快照。UI 验证完整轮次身份，并只接受当前轮更高修订，旧连接最后消息不能把 T1 复活。

可采用每订阅一个“最新快照待发送槽”，合并中间进度和模型输出更新；缓冲满时替换为更新快照，慢消费者不会拖慢图，不要求补齐中间事件。完整输出受内存/输出上限约束，更新频率经测量设定；不为每 token 保留一个对象或独立历史快照。发送失败只关闭观察端；重连再次原子订阅当前状态，没有 event log、永久游标、SSE 或 replay。

诊断允许错误类别、节点类别、成功/拒绝/迟到计数、持续时间和不含内容的资源计数；默认在内存聚合，若写诊断文件只能使用批准的无内容白名单。关联 ID 默认仅在当前内存排查使用，不把窗口、文本摘要、完整路径或原始 provider 请求放入持久诊断。故障说明可指导用户重新连接、开始新轮、核对模型配置或另选导出目标，不能要求上传会话或启用含内容 Trace。
