# 本地摘要工具工程计划

推荐采用一个同步 Python CLI：主进程管理输入、总时限与文件提交，一个可终止的本地模型工作进程负责推理。最终摘要保存为一个 UTF-8 Markdown 文件。这个边界符合个人电脑、有界任务、允许中断后重跑的需求，维护成本主要集中在文件处理和模型适配器。

本次是 `/brainstorming` 规划，依据只有 [本地摘要需求](../../fixtures/planning/briefs.md#p01-本地摘要工具)，项目尚无实现、锁定依赖、模型接口或测试材料。以下模块、参数和验收均为拟议内容，未执行模型、未创建业务代码，也未验证真实性能。

## 1. 可交接的产品合同

一次命令扫描用户给定目录，读取选中的文本，在本地模型上生成综合摘要，完整提交到用户指定文件后才报告成功。中断可以丢失未提交的工作；用户重新运行就是一次新的计算，无恢复现场和沿用旧模型结果的承诺。已有输出默认不能覆盖，只有当前命令显式给出 `--overwrite` 才能替换指定目标。

为便于实现，先采用以下可调整假设；它们是第一版配置建议，不是已测容量或 SLO：

| 项目 | 第一版假设与触发后的行为 |
|---|---|
| 文件选择 | 扫描根目录及子目录中的普通 `.txt`、`.md` 文件，按相对路径排序；不跟随扫描中遇到的符号链接。无匹配文件明确失败。 |
| 汇总粒度 | 一次任务生成一份综合摘要，并附所用相对文件名。没有要求逐文件输出，因此首版不增加多产物提交。 |
| 编码 | 严格 UTF-8；不可读、解码错误或扫描时变化的输入使整次任务失败，不静默跳过或提交不完整摘要。 |
| 输入界限 | 默认最多 100 个文件、单文件 256 KiB、总计 1 MiB；读取中继续累计实际字节，不能只信文件元信息。模型上下文上限是另一道限制。 |
| 时间 | 默认总执行预算 300 秒，可由命令设置正数；使用单调时钟从参数校验后的任务开始计时，含扫描、模型初始化、推理与交付。终止后的进程清理另有最多 2 秒目标，须真实适配器验证。 |
| 并发与成本 | 每次命令最多一个模型调用、一个推理子进程；不自动重试、修复或切换模型。没有远端计费；本地 CPU/GPU、内存、输入/输出及时间需要限制。多条用户命令同时启动时的总 GPU 容量暂不承诺。 |
| 输出规模 | 首版模型输出上限拟为 1,024 token；最终值须与实际模型能力共同确认。拒绝、空输出或截断输出不能当完整成功结果。 |

目录到单份摘要这一选择若不符合使用习惯，可改为逐文件摘要，但要同步重定输出命名、部分成功和覆盖合同。真实模型的上下文、最小运行环境和推理耗时未知，不能据上述数字宣称该电脑能在 300 秒内完成最大输入。

## 2. 入口、模块与事实拥有者

拟定入口示例：`local-summary INPUT_DIR --output OUTPUT.md [--overwrite] [--timeout-seconds 300] [--max-input-bytes 1048576]`。使用者是当前操作系统用户，授权范围是明确指定的输入目录和输出文件。命令只接受本地路径，模型与 prompt 不得决定读写路径、执行 shell 或访问其他工具。

| 拟实现组件 | 职责及调用合同 | 所拥有的事实 |
|---|---|---|
| `cli` | 解析参数、校验目录/目标、装配配置；调用任务控制器；将结果映射为退出码 | 用户明确给出的路径、覆盖许可与资源配置 |
| `input_reader` | 在边界内确定性扫描，受限读取并生成内存快照；返回相对路径、字节数、内容摘要及文本 | 本次实际用于推理的输入快照；原文件仍由用户管理 |
| `task_runner` | 持有 deadline、检查每个阶段的剩余时间，监督模型子进程，验证结果后调用输出器 | 仅本次进程内的阶段、时限、完成/错误结果 |
| `model_adapter` | 把文本作为数据装配到固定提示模板；通过本地绑定或 stdio 可执行文件调用现有模型；返回完整文本、完成原因、模型版本、可用的 token 统计 | 一次模型响应及其协议解释；没有文件写入和业务授权权力 |
| `artifact_writer` | 写同目录临时文件、校验并原子提交最终目标；处理覆盖规则及清理 | 成功交付的最终文件及提交结果 |

这些是模块责任，不要求各自拆包或服务。测试通过构造参数注入 fake 模型、时钟与输出失败点，实际 CLI 默认装配经验证的本地模型适配器。

返回合同：成功时 stdout 显示最终路径、读取文件/字节数和总耗时；阶段提示及错误写 stderr。退出码拟为 `0` 成功、`2` 参数或输入/上下文超限、`3` 输出存在且未授权覆盖、`4` 输入/输出 I/O 失败、`5` 模型失败或结果不完整、`124` 超时、`130` 用户中断。失败消息指出阶段、原因和可行下一步；不输出完整原文、prompt 或模型内部信息。stdout 提示失败不能导致再次推理或重复写文件，用户可按已知目标路径检查交付事实。

## 3. 正常路径与关键失败窗口

正常流程为：校验输入及输出路径 → 有界读取、冻结内存快照 → 校验模型上下文 → 本地模型推理 → 检查完整结果与剩余时间 → 原子提交文件 → 输出成功摘要。

任务阶段在内存中表达即可：`reading → summarizing → writing → succeeded`；任一未提交阶段可进入 `failed / timed_out / interrupted`。没有需要保存的人工等待点。用户中断停止后续推进，工作进程退出后释放资源；下次运行从头计算。

| 窗口 | 明确的处理与用户可见结果 |
|---|---|
| 扫描/读取失败、目录过大 | 不启动模型，不提交输出；报错指出问题文件或哪个上限被触发。限制遍历项数和路径深度，或在遍历中持续执行 deadline，避免无界目录拖住任务。 |
| 输入超过上下文 | 在推理前计入模板、文件标记及输出预留，使用实际 tokenizer/模型上下文配置校验；超出就拒绝并提示减少输入。首版不静默截断，也不自动增加多轮分块推理。 |
| 模型阻塞、超时或 Ctrl-C | 主进程停止接收结果，要求子进程取消，随后按清理期限 terminate/kill 并回收；迟到结果不得交给输出器。仅 `Future.result(timeout=...)` 不构成停止推理。 |
| 进程尚未确认停止 | 明确报告清理状态，不能宣称算力已释放。真实 SDK/native/GPU 的停止能力必须纳入适配器验收；无法可靠停止时该适配器不满足时限合同。 |
| 模型拒绝、空响应、非法或截断结果 | 归为模型失败，保存简短诊断，不覆盖最终文件；不自动尝试另一模型。 |
| 临时文件写入或提交失败 | 删除本次可确认归属的临时文件；旧输出保留。重跑仍受当前覆盖开关约束。 |
| 提交后、成功提示前中断 | 完整文件可能已存在；不声称撤回已完成写入。用户检查明确目标，下一次未加覆盖参数时应拒绝覆盖，避免无意丢结果。 |

总时限由主进程持有，每次模型调用只获得剩余时间并预留提交/清理时间；进度输出不暂停计时。到期后不启动新调用或新提交。已经开始的底层文件系统调用可能越过 deadline，因此应将“到期不再推进”和“进程何时退出”分开记录；首版以普通本地磁盘为运行条件，不宣称对失联挂载盘、内核阻塞或 GPU 驱动故障具有严格终止时限。

## 4. 文件与模型合同

输入读取默认拒绝扫描内符号链接、管道、设备文件及目录外解析结果；输出路径由用户给定，禁止与任何输入文件实际指向同一文件，即使指定覆盖也不得破坏源文档。输出位于输入目录内时，将指定输出和本工具的临时文件排除出扫描；同目录中其他文本仍是正常输入。目录根可在入口解析为固定绝对路径，后续校验保持同一边界。上述做法适用于当前用户控制的普通目录；如以后允许不可信进程并发替换路径，需要补充基于目录句柄的防竞态访问或隔离目录。

完整结果先写输出目录内的独占临时文件，使用限制性权限，写完 flush/fsync 后再提交。未指定覆盖时必须采用原子的“不存在才创建”，例如同文件系统支持时使用临时文件硬链接到目标再移除临时文件；存在则失败，不能采用“先 exists 检查再 replace”。指定覆盖时使用同目录原子替换。若文件系统不支持所选原语，则明确失败，不能偷偷退回会覆盖既有文件的写法。文件提交后才报告成功；目录同步按目标平台支持情况处理，断电耐久性必须注明平台限制。意外终止可能留下临时文件；只清理能确认属于本工具且不在使用中的文件，不扫描删除用户其他内容。

产物拟采用 UTF-8 Markdown，包含摘要正文、来源相对路径、工具/模型/prompt 版本及生成时间；版本与少量诊断可以合并到文件尾，无需独立数据库或每次运行的永久日志。用户决定最终文件保留与删除；工具不另存原文、prompt、缓存或长期记忆。

模型入口需要确认已部署模型支持本地进程内绑定或 stdio 调用，并锁定相应运行时/依赖和模型文件版本；不得在启动时下载模型、发送遥测或回退云端。如果现有部署仅有 HTTP 服务，即使是 loopback 也与当前“不访问网络”要求不一致，这会阻止该适配器直接接入，需提供本地调用方式。当前没有此接口材料，尚不能选择具体 SDK。

文本放在明确的数据区，固定提示说明其内容仅供摘要；模型可生成的文本不会成为命令、文件路径、权限声明或工具调用。输出中的“请运行某命令”等内容仍然只是文字。隔离子进程用于可取消性，不自动构成网络/秘密沙箱；应使用无网络能力的适配器、关闭已知联网功能，并在实际宿主的断网/出口受限环境验证离线运行。推理子进程只收到必要文本与模型配置，不复制无关凭据。

## 5. 项目适配与验收记录

| 能力/项目条目 | 本项目选择与机制 | 拟验收、限制和重评条件 |
|---|---|---|
| C01 产品完成 | 采用明确的文件提交成功条件；容量与时间先用假设配置 | 最大/最小合法输入、超限和失败均有明确定义；真实耗时待测 |
| C02 入口/身份 | 简化为 CLI 参数及当前系统用户；路径/覆盖许可由入口强制 | 测无效目录、输出冲突、路径别名和源文件保护；多用户时重评认证 |
| C03 数据/存储 | 采用原子文件交付；执行记录合并在内存，版本信息合并到产物 | 写入中断、磁盘错误、不覆盖竞态、旧文件完整性；不建关系表 |
| C04 状态/恢复 | 简化为进程内阶段和退出码，中断后重算 | 超时、中断及提交临界点行为；需求变为不能丢工作时重评持久化 |
| C05 调度/执行权 | 同步调用者承担等待；每条命令监督一个工作进程，省略独立队列 | 核对进程退出/回收；多人或需统一 GPU 排队时才评估共享调度 |
| C06 工具/副作用 | 模型只读计算，唯一写动作是明确输出；防覆盖由输出器负责 | 模型文字不能改变路径；无需持久工具账本、外部对账和审批系统 |
| C07 模型适配 | 采用一个本地适配模块，完成原因、异常、上下文与输出上限明确 | fake 测协议；真实模型测离线启动、取消、输入限制，仍待验证 |
| C08 上下文/产物 | 有界输入快照与文件产物；无 RAG、长期记忆或共享上下文 | 多文件来源可追溯；输入过长拒绝；需要大语料才重评分块 |
| C09 安全/隔离 | 采用文件边界、最小输入、纯文本消费和离线运行 | 链接越界、特殊文件、注入文本、网络出口与子进程清理 |
| C10 时间/资源 | 采用总 deadline、单次调用和输入/输出上限；无费用账本 | 可控时钟测边界；真实挂起模型测停止能力；并行/自动重试时重评累计预算 |
| C11 结果/观测 | 简化为文件、stdout/stderr、阶段/耗时/退出码 | 展示失败不重做业务；没有订阅需求，不建 SSE/游标/事件库 |
| C12 交付/版本 | 本地安装运行合同与锁定依赖、模型/prompt 版本 | 新环境离线启动、错误配置；无容器、集群或在途状态迁移需求 |
| C13 验证/运维 | 用临时目录、fake、可控时钟及小型真实本地验收 | 当前无需服务值班、业务数据库灾备；用户保管输出，任务可重算 |
| C14 业务质量 | 小型版本化摘要样本集和人工核对 | 事实保真、关键点覆盖、引用来源、长度/时延分别评估；无需训练或自优化平台 |

## 6. 实施增量与交接顺序

1. **首个可运行闭环。** 完成 CLI → 受限读入 → 可替换模型适配器 → 完整性检查 → 原子文件交付 → 明确失败及退出码。时限、取消、默认不覆盖、离线边界纳入同一增量，不能只做快乐路径。初期用 fake 完成工程验收；交付为可用工具前必须接入实际本地模型并验证其停止能力。规模为中等，模型接口是主要不确定性。
2. **关键失败与使用说明。** 覆盖超限、异常文本、路径保护、输入变化、模型阻塞/截断、磁盘失败、已存在输出及提交后提示丢失。临时目录验证不修改源文件或旧输出；用受控阻塞子进程验证主进程确实回收子进程。补齐安装、运行、错误处置和临时文件清理说明。相对工作量小到中，依赖首个闭环。
3. **真实质量与性能定标。** 用明确版本模型和少量代表性材料核对质量，并测文件量/文本长度下的总耗时与内存占用，据此调整默认限制。若大输入无法在预算内完成，先给清晰拒绝和操作建议；分块摘要属于后续有证据支持的能力变更。相对工作量取决于真实推理性能。

回退到旧程序只涉及程序/依赖版本，已成功生成的文件属于用户产物，不自动删除或重写。改变输出格式时保留明确格式版本；由于没有在途恢复与数据库，首版无需迁移执行历史。

交接给实现者的第一步是确认本地模型调用、取消和上下文能力，再锁定运行环境。完成标准是：实际 CLI 能在不联网的环境从合法目录生成完整文件，所有当前输入/覆盖/时限保护在真实入口生效，关键失败路径有证据，并附真实模型质量与性能结果。此报告已完成材料检查与规划；上述实现和验收全部待完成。
