# 本地恢复合同

公开入口仍为 `resume(db_path, model, tools, fault=None)`。一个 `db_path` 对应一份已接受决策和最终文本；上层继续保证同一数据库只有一个活跃执行者。调用保持同步，独立工具按原决策顺序执行。所有输入、参数和结果须能编码为 JSON，最终输出须为字符串。

`model.plan()` 的完整输出经结构、调用身份和业务参数冲突校验后，在一个 SQLite 事务内与调用集合一起接受。此后重开入口使用已保存的决策，不再重新计划。同一业务 key 的参数按与模拟器相同的 JSON 编码比较；同内容的新 `call_id` 引用同一操作结果，仍各有一条配对消息；同 key 不同内容在派发前拒绝整份决策。

## 持久事实

| 记录 | 拥有的事实与关联 |
|---|---|
| `run` | 一份原始完整决策、`decision_id`、已提交最终文本；`id=1` 唯一 |
| `calls` | `call_id`、原顺序、所属运行和 `operation_key`；每个调用有独立结果就绪标志 |
| `operations` | 稳定业务 key、规范参数、可复用结果、产生该结果的尝试引用 |
| `attempts` | 每次 execute/lookup 的调用、操作、开始/结束时间、状态和错误；未决/拒绝历史保留 |
| `messages` | 每个 `call_id` 唯一的结果消息和消费标记 |
| `finish_attempts` | 本次消费的完整消息快照、模型完成尝试及结局 |

外键在实际连接中启用；`synchronous=FULL`。数据库使用 `user_version=1`。原调用和结果直接保存在 SQLite 内，没有仅留摘要或外部对象引用。索引用于按操作找历史尝试；原始顺序由 `calls.position` 决定。

## 提交与恢复

| 已保存的事实 | 恢复动作 |
|---|---|
| 决策和调用已接受，无 execute 尝试 | 执行原调用 |
| execute 已登记但没有可靠结果 | 先 `lookup` 原业务 key；不能仅凭 pending/unknown 认定未执行 |
| lookup 返回可靠结果 | 保存结果与核实尝试，复用到原调用 |
| lookup 返回 `None` | 按本模拟器合同视为确定未执行，允许下一次安全执行 |
| lookup 异常 | 保存 unavailable 记录，抛 `RecoveryUnavailableError`；此入口不重发工具 |
| 某操作已有结果、另一个尚未完成 | 复用已有结果，剩余调用按各自状态恢复 |
| 结果已保存、消息未生成 | 按原 `call_id` 补齐一次消息 |
| 消息已保存 | 不重复添加；全部消息齐全后按原顺序调用 finish |
| 最终文本已提交 | 直接返回原文本，不访问模型或工具 |

execute 尝试在工具调用前提交。外部 execute/lookup/finish 调用均不占用本地写事务。工具异常后只核实一次；若确认未执行，则抛 `ToolExecutionError`，由后续 `resume` 决定继续，避免单次入口无界重试。查询恢复可在后续 `resume` 独立推进。

给定模拟器用 `ValueError` 拒绝内容冲突，因此记录为持久 rejected，后续恢复继续拒绝。其结果回显 `operation_key` 与 `value`，恢复时核对这两个字段和已接受参数；这覆盖了“下游拒绝已发生、本地尚未来得及记录拒绝便退出”的窗口。其他真实适配器若使用不同错误分类或结果格式，需要独立定义/验证内容冲突和结果身份合同。

三个 fault 钩子仅在对应新事实提交后调用：`decision_saved` 的身份为 `None`，`result_saved`、`message_saved` 为原 `call_id`。已提交的钩子事实不会因重入重复写入或重复触发。回调异常原样向上传播；进程直接退出后，下次打开数据库仍按上述记录恢复。

最终文本、消息消费标记和成功的 finish 尝试在同一事务内提交。若 finish 的远端执行完成但文本尚未本地提交时退出，接口没有模型查询或幂等能力，恢复可能再次调用 finish；持久历史会保留两次尝试，工具和消息不会重做。plan 返回但尚未接受的窗口也可能重新调用 plan。这些窗口未声称模型调用恰好一次。

## 错误与存储兼容

- `RecoveryUnavailableError`：保留原数据库，待查询可用后使用同一路径调用 `resume`。
- `ToolExecutionError`：已核实未执行，可在下次入口重试。
- `ValueError`：决策不合法或业务内容冲突；已接受的冲突调用不会通过更换 call_id 自动绕过。
- `RecoveryStateError`：版本不支持或旧数据缺少恢复依据。不要清空有潜在业务历史的数据库以“修复”错误。

旧版本只保留 `outputs`：有历史行时拒绝自动恢复，保留旧数据供人工查看；没有历史行的空旧库可以初始化新格式。未来版本和未知未标版本的恢复数据也明确拒绝。没有实现旧历史回填、旧进程同时运行或降级读新数据的兼容保证；升级需停止旧执行者，保留原数据库。旧未完成任务若丢失全部决策和调用信息，无法从最终字符串反推安全恢复依据。

去重与结果保留范围为当前 `db_path`；不提供新任务/reset API、跨数据库本地结果共享或自动清理。不同数据库的同 key 冲突仍由给定下游防重合同处理。使用者需保护文件并保留全部关联记录直到不再需要恢复。

## 运行验证

在此目录运行：

```sh
python3 -B -m unittest -v test_engine.py
```

测试直接调用公开入口，使用原始 `fakes.py` 和标准库派生故障适配器，SQLite 文件位于临时目录。覆盖 7 个异常钩子位置、7 个对应 `os._exit` 位置、外部调用前/生效后退出、finish 响应空窗、冲突拒绝记录空窗、部分完成、响应丢失、持续查询不可用、结果事务失败、业务 key 复用/冲突与历史关联。没有真实网络、账号、模型服务或业务写入。

这证明本地单执行者协议与实际进程退出恢复；没有验证物理断电、文件系统损坏、SQLite 文件遗失、真实下游防重保留期/查询一致性、远程模型成本或集群并发。
