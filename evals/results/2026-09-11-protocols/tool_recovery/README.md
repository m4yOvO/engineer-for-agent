# 工具桥接模块

请使用 /build 修复当前模块。它是单用户、本地 Python + SQLite 项目；上层已保证同一 db_path 只有一个活跃执行者。本次不构建队列、HTTP 服务或多机调度。只修改 engine.py、增加必要测试和说明，fakes.py 是给定的外部合同模拟器，不要修改。

入口保持 resume(db_path, model, tools, fault=None)。model.plan() 给出一份决策和多个独立工具请求，model.finish(messages) 消费对应结果并产生最终文本。tools.execute(operation_key, arguments) 可能在外部已生效后丢失响应；tools.lookup(operation_key) 的非空结果是权威已完成结果，None 在本夹具中表示确定未执行，异常只表示查询不可用。工具的业务 key 防重与内容冲突由模拟器实施。所有数据都在临时本地文件中，无真实网络、凭据或业务写入。

用户反馈：任务恢复时重复向模型询问，也会重新调用已完成工具；部分工具完成后中断，恢复结果与原请求偶尔对不上。

需要完成：
- 已接受决策与调用可跨进程恢复。每个调用的结果与原 call_id 对应；完成结果可重复读取，不能因缺少另一个结果而重做它。
- 外部成功但本地结果未知时可以核实恢复；查询不可用时保留可恢复现场并向调用者报告，不能为获得结果再次盲调工具。
- messages 使用 [{"call_id": ..., "result": ...}]，按原决策顺序，调用结果恰好配对一次。所有工具结果齐全后才能调用 finish。
- 最终文本保存后重复 resume 返回原结果；运行记录能关联决策、工具请求、尝试、结果与消费，不能只保存最终字符串。
- 同一业务操作被新的 call_id 引用时可复用可靠结果；同 operation_key 改参数必须拒绝，不能误复用旧结果。
- 提供故障钩子：对应事实可靠保存后调用 fault("decision_saved", None)、fault("result_saved", call_id)、fault("message_saved", call_id)。钩子可抛异常或使进程直接退出；恢复仍要满足上述承诺。未传钩子正常工作。
- 需要验证实际入口、重开/进程退出、多个工具部分完成、结果/消息保存后的恢复和下游响应丢失。可改内部表结构，但保留公开签名。
